# 실측 카메라 화각 정렬 · #101

## 문제와 원인

사용자 비교 사진에서 기본 카메라와 Dobby 모두1x인데 Dobby의 옷이 더 크게 보였다. 두 사진의 촬영 위치·거리는 통제되지 않았으므로 사진만으로 광학 차이의 비율을 단정하지 않는다. 코드에서는 별개의 확실한 추가 확대를 확인했다.

기존 ARSCNView는 상·하단 조작 영역을 포함한 휴대폰 전체402×874pt를 채웠다. 1920×1440 센서 영상을 세로로 회전하면3:4 비율이다. 이 원본을 가로402pt로 표시할 때 적정 높이는536pt지만, 전체874pt 높이에 aspect-fill하면서 피사체가 약1.63배 커졌다. 상·하단을 반투명 영역으로 덮어도 ARSCNView의 확대는 취소되지 않는다.

이 문제는 측정값에0.61 같은 보정 상수를 곱하거나 배율 이름을 바꾸는 방식으로 해결하지 않는다.

## 변경된 표시 기준

- `CameraPhotoViewport`가 조작 영역을 제외한 공간에 실제 사진 원본 비율을 유지하며 배치한다. 세로는 상단146pt·하단192pt, 가로는 우측180pt를 제외한다.
- 실제 ARFrame 영상의 가로·세로 크기를 작은 상태 값으로 전달한다. 크기가 같으면 화면 상태를 다시 발행하지 않으며, 사진 창 계산을 위해 RGB 복사·인식 모델 실행을 추가하지 않는다.
- 402×874pt 화면의4:3 센서는 세로402×536pt, 원점(0,146)으로 표시한다. 874×402pt 가로 화면은536×402pt, 원점(79,0)으로 표시한다.
- 다른 기기·영상 비율에는 가로세로 중 들어오는 크기로 맞춘다. 남는 영역을 채우려고 사진을 늘리거나 더 확대하지 않는다.
- 1x는 원본 센서 영상 전체를 보여 준다. 2x는 그 사진 창을 기준으로 중앙2배 미리보기를 보여 주며, 촬영은 기존의 등록된 RGB·깊이·보정행렬 공통 크롭을 유지한다.
- 초점 탭·노출 표시와 윤곽선은 실제 ARSCNView bounds와 ARKit 표시 변환을 그대로 사용한다. 휴대폰 전체 기준의 추가 오프셋이나 배율 보정을 곱하지 않는다.
- 분석 정지 사진의 창 크기는 셔터 순간에 고정한다. 결과에 사진을 넘길 때도 그 창을 사용하며, 헤더·셔터 높이를 다시 빼서 이중 크롭하지 않는다.
- 기존 저장 기록에 있는 `presentationCrop`은 보존한다. 새로운 표시 수정이 예전 사진·수정점·측정값을 재작성하지 않는다.

원본 JPEG, sceneDepth, intrinsics, ML 입력과 실측 계산은 표시 창과 별개의 기존 계약을 유지한다. 실측 촬영의 인식 후 주황색 셔터,1x·2x Liquid Glass 버튼, 초점·노출 동작도 유지한다.

## 검증과 실기기 비교

좌표 테스트는 세로·가로·태블릿·비표준 영상 비율, 초점 정방향/역방향 변환,2x RGB·깊이·보정행렬 정합을 검증한다. 합성 UI 테스트는 실제 화면 사진 영역,1x·2x 픽셀, 분석 중 구도 유지와 결과 편집을 확인한다. 합성 테스트는 실제 기기의 광학 화각이나 센티미터 오차를 증명하지 않는다.

2026-10-26 검증 결과:

- Core40개 통과: 새 사진 창8개, 초점 표시 변환9개, 결과 표시 크롭10개, RGB·깊이 등록 크롭13개.
- Presentation49개 통과: 사진 편집·확대기·분석 사진 기하43개, 촬영 메타데이터6개.
- 서로 다른 UI10개 통과: 전체 원본·분석 중 픽셀 유지, 중앙2x 단일 크롭, 가로 배치,1x·2x 초점/노출 조작, 촬영·결과 구도와 결과점 편집. 마지막 배율 조작 테스트는 아래 보완 후 단독 재검증으로 통과했다.
- iPhone 대상 앱·QuickCopyWidget 빌드 성공. 코드 서명과 실제 아이폰 설치는 수행하지 않았다.
- 초기 픽셀 검증 지점 하나가 분석 중 합성 안내 캡슐에 가려져, 안내 밖의 배경과 옷 내부 지점을 비교하도록 수정했다. 합성 조작 영역 크기도 사진 창으로 명시했다. 노출 검증은 XCTest 명령의 명목 거리와 UIKit 팬의 실제 전달 거리가 같다고 가정하는 대신,1x·2x에 동일한 드래그를 보내 응답이 같은지 비교한다.
- 로그: `/private/tmp/dobby101-core-tests.log`, `/private/tmp/dobby101-ui-tests.log`(Presentation49개), `/private/tmp/dobby101-ui-final.log`(UI9개 통과·수정 전 노출 거리 가정1개 실패), `/private/tmp/dobby101-zoom-control-final.log`(보완한 UI1개 통과), `/private/tmp/dobby101-device-build-final.log`.

실제 아이폰에서 기본 카메라와 위치·거리·설정을 통제한 비교는 아직 수행하지 않았다.

기본 카메라와의 실제 비교는 아래 조건을 맞춰야 한다.

1. 아이폰 위치·높이·기울기를 고정하고 같은 옷과 주변 바닥의 두 기준점을 사용한다.
2. 기본 카메라의 사진4:3·1x를 기준으로 비교한다. 접사 전환이나 다른 기본 렌즈 설정이 있다면 그 상태를 함께 기록한다.
3. 휴대폰 전체 스크린샷 대신 실제 사진 영역을 기준으로 옷의 가로 폭과 두 기준점 위치를 비교한다.
4. Dobby1x→2x→1x, 촬영→분석→결과에서도 위치와 크기가 일관적인지 확인한다.
5. 같은 기록의 측정값이 표시 변경 때문에 바뀌지 않는지 확인한다.

## Apple 문서

- [ARFrame 표시 변환](https://developer.apple.com/documentation/arkit/arframe/displaytransform(for:viewportsize:)): 영상 좌표를 실제 뷰 크기·방향에 맞춰 변환한다.
- [ARKit 지원 영상 포맷](https://developer.apple.com/documentation/arkit/arconfiguration/supportedvideoformats): 포맷은 기기·OS에 따라 달라지므로 고정된 센서 해상도를 측정 좌표에 가정하지 않는다.
- [AVCaptureDevice 배율](https://developer.apple.com/documentation/avfoundation/avcapturedevice/videozoomfactor): 카메라 배율과 표시 영역의 추가 크롭은 구분해야 한다. 이번 수정은 카메라 하드웨어 배율을 바꾸지 않는다.
