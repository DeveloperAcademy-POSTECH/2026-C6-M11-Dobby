# 상·하의 자동 판별 · 2026-10-01

## 사용자 흐름

홈에서 **옷 촬영 · 실측 → 실측 촬영**을 연다. 촬영 전에 상의·하의를 선택하지 않는다.

1. 한 벌을 바닥에 평평하게 펼친다. 상의의 소매와 하의의 양쪽 바짓단까지 전체가 보여야 한다.
2. 카메라가 의류 분류 모델로 상·하의를 구분하고 해당 영상의 측정점 구조와 옷 윤곽을 함께 확인한다.
3. 확인된 종류와 함께 **상의 인식 완료** 또는 **하의 인식 완료** 안내가 나온다. 같은 옷의 깊이·카메라 안정성을 연속 확인한 뒤 셔터가 활성화된다.
4. 촬영한 RGB·깊이를 고정한다. 그 사진에서 종류·점·윤곽을 다시 확인하고 그 결과에 맞는 항목을 계산한다.
5. 결과를 확인하고 저장한다. 부분 실패 항목에는 임의의 길이를 표시하지 않으며, 사진에서 두 점을 직접 확인할 수 있다.

**모델별 사진 진단**의 상의·하의 버튼은 각 모델의 점 위치를 검증하는 도구다. 정상 실측 촬영에 사용할 모델을 선택하는 버튼이 아니다.

## 종류를 정하는 기준

공급된 패키지의 `clothes_image_detection` 모델이 15개 의류 카테고리를 분류한다. 가장 높은 **개별 카테고리** 점수의 종류를 선택한다. 카테고리 점수를 그룹별로 합산하거나, 독립적인 상의·하의 pose 모델의 점수를 서로 비교하지 않는다.

| 카테고리 | 연결 |
|---|---|
| T-shirt, Shirt, Polo, Sweater, Hoodie, Blazer, Jacket, Coat, Denim Jacket, Sports Jacket | 상의 `top11` |
| Jeans, Long Pants, Shorts | 하의 `bottom7` |
| Skirt, Dresses, 등록되지 않은 카테고리 | 자동 실측 미지원 |

분류 결과가 흐리거나 서로 다른 종류가 비슷하게 나오면 확정하지 않는다. 최고 개별 점수 `0.10`, 다른 종류의 최고 개별 점수와 차이 `0.01`을 초기 판별 기준으로 사용한다. 같은 상의 그룹 내 Shirt/T-shirt 등의 차이는 상·하의 판별을 막는 근거로 사용하지 않는다. 이 값은 동작을 위한 초기 제한이며 정확도나 확률이 보정된 기준이 아니다.

종류를 선택한 후에는 해당 pose 모델의 점과 **같은 이미지의 Vision 전경 마스크**를 연결한다. 몸통·소매 또는 양쪽 다리·가랑이의 배치와 실제 윤곽이 맞는지도 확인한다. 상의의 기존 180도 방향 회복과 보수적인 부분 연결을 유지하며, 찾지 못한 측정점을 만들어내지 않는다. 배경 전체를 옷처럼 연결한 마스크는 종류 확인 근거로 사용하지 않는다.

분류와 윤곽 근거가 충분하지 않으면 기다리는 상태를 유지한다. 지원하지 않는 카테고리는 안내를 표시하며 해당 종류에 상의·하의 모델을 임의 적용하지 않는다. 높은 분류 점수나 `supported` 진단은 점 위치 정확도나 cm 오차 보증이 아니다.

## 프레임과 항목의 일치

- 실시간 인식은 촬영 준비 안내에만 사용한다. 실측 사진에 그 점이나 마스크를 복사하지 않는다.
- `GarmentLandmarkSet.garmentKind`는 고정된 촬영 사진의 판별 결과다. 모델 버전과 함께 기록되며 기존 기록에서 값이 없으면 미지정으로 읽는다.
- `GarmentMeasurementDefinitionProviding`은 해당 결과의 종류·모델 버전·점 ID 계약을 확인하고 측정 항목을 반환한다. 변경 가능한 “마지막 인식 종류” 상태를 읽지 않는다.
- workflow는 RGB·깊이와 점의 session/frame ID, 모델 출처, 동적으로 선택한 항목을 검증한 뒤 계산한다.
- 상의에서 하의로 바뀌거나 모델 버전이 바뀌면 준비 상태의 연속 확인을 다시 시작한다. 움직임·회전·오래된 분석 결과의 무효화 조건도 유지한다.
- 인식 실패 사진의 수동 복구는 미확정 사진을 상의·하의로 추정하지 않고 **기타 · 두 점 사이**부터 시작한다.

## 응답성과 윤곽 표시

분류 모델과 pose 모델은 준비 후 캐시된 모델을 사용한다. 매 영상에서 분류한 종류의 pose 모델만 실행한다. 재검사의 방향과 횟수는 제한하며, 이미지·점·마스크는 다른 호출의 결과와 섞이지 않는다.

실시간 분석은 기존처럼 한 작업만 진행하며, 기다리는 영상을 쌓지 않는다. 셔터를 누르면 실시간 분석을 중단하고 고정된 사진의 추론으로 넘어간다. 표시용 윤곽 다듬기·네이티브 애니메이션과 동작 줄이기 처리는 [윤곽 표시 개선](Garment-Silhouette-Presentation.md)을 따른다. 종류 판별은 측정점 위치나 측정용 마스크를 움직이거나 팽창시키지 않는다.

## 지원 조건

- 지원 모델 범위는 펼친 긴팔·반팔 상의와 바지·반바지다. 치마·원피스·옷걸이에 걸린 옷은 자동 실측의 지원 범위가 아니다.
- 소매를 몸통에 겹치거나 바짓단을 서로 붙이면 구조를 확인하기 어렵다. 한 벌 전체를 펼치고 두 바짓단 사이가 보이게 놓는다.
- 사진의 몸통/다리 구조나 점 근거가 불충분하면 촬영 준비가 되지 않을 수 있다. 불명확한 종류를 성공처럼 표시하는 대신 배치와 조명을 바꿔 재인식한다.
- 실제 실측은 LiDAR 기기에서만 수행한다. 합성 미리보기의 종류와 치수는 카메라·ML 성능의 근거가 아니다.
- 의류 종류의 일반적인 정확도, iPhone의 지속 처리 시간과 줄자 대비 오차는 실물 기준 데이터로 별도 확인해야 한다.

## 구현

- `Capture/AutoGarmentLandmarkProvider.swift`: 같은 이미지의 분류·해당 pose 모델·윤곽 확인, 방향 회복과 고정 사진 결과.
- `Core/GarmentClassifierRoutingPolicy.swift`: 카테고리별 모델 연결과 미지원·불확실한 분류 처리.
- `Core/GarmentKindSelectionPolicy.swift`: 선택한 종류의 점 구조·실루엣 근거 확인.
- `Core/AutomaticGarmentKind.swift`: 종류·모델·스키마 계약.
- `Core/AutomaticMeasurementWorkflow.swift`: 고정된 결과의 측정 항목 선택과 프레임·출처 확인.
- `Core/LiveCaptureReadiness.swift`: 종류·모델이 바뀔 때 연속 준비 상태 초기화.
- `UI/GarmentCaptureFlowView.swift`, `UI/LiDARLabView.swift`: 선택 없는 촬영 진입, 종류 안내와 결과 분류.

인식된 21장의 실시간 결과와 고정 사진 결과에서 종류·모델·점·마스크·프레임 출처와 측정 항목의 일치를 확인했다. 회전 사진 15건도 같은 계약을 통과했고, 치마 사진 6장과 빈 영상 3장은 자동 실측에 진입하지 않았다. 마스크 내부 구멍을 가랑이로 오인하는 회귀 사례도 추가했다. 실제 바짓단 사이의 배경이 바깥까지 이어져야 하의 구조로 인정한다.

시뮬레이터에서 전체 `prepare()`는 Vision 오류 코드 9로 실패한 시도도 보존했다. 단계별 재검사에서 번들 분류 모델과 상의·하의 측정점 모델 준비는 통과했고, Apple의 전경 마스크 요청만 같은 오류로 실패했다. 분류 모델을 변경하거나 윤곽 오류를 무시하지 않았다. 카메라·LiDAR·Apple 전경 모델이 함께 동작하는 실물 촬영과 줄자 대비 오차, 지속 처리 시간은 iPhone에서 확인해야 한다.

재현 자료와 테스트 범위는 [자동 판별 검증 기록](Validation/automatic-garment-recognition-2026-10-01.json)에 정리했다. Mac 처리 시간과 합성 깊이 검증을 iPhone 성능이나 cm 정확도로 해석하지 않는다.

### 최신 의류 데이터 모델 통합

`main`의 의류 데이터 모델 추가(#15)를 작업 브랜치에 반영했다. 이동된 앱 진입 파일·기본 에셋의 빌드 참조를 갱신하고, 기존 판매 채널과 새 저장 모델의 중복 `ExportChannel`을 하나로 통합했다. 채널의 rawValue·URL·기존 키와 `ExportRecord` API를 유지했다. SwiftData 저장소를 기존 LiDAR 기록 흐름에 연결하는 변경은 포함하지 않는다.

통합 후 Core 360개와 네이티브 Debug·Release 빌드를 다시 확인했다. 새 임시 UI 프로젝트의 홈·링크 5개, 상·하의 촬영 2개, 번들 모델 2개, 저장 모델·채널 호환성 1개로 총 10개 회귀 검사가 통과했다. [통합 검증 기록](Validation/automatic-garment-main15-integration-2026-10-01.json)에 소스 해시와 실행 결과를 남겼다.

### #17 충돌 해결과 현재 파일 구조

`main`의 #17 변경에 맞춰 앱 진입 파일과 기본 에셋은 `Dobby/Dobby/` 안의 동기화된 앱 소스 폴더를 사용한다. Xcode 프로젝트와 UI 테스트 실행기에서 이전 루트 위치의 중복 참조를 제거했다. `GarmentEnums.swift`는 main의 중복 enum·미사용 표시 속성 제거를 따르고, 공용 `ExportChannel`의 `Codable`과 기존 식별자·URL을 유지한다.

기능 코드와 원본 모델은 그대로 보존했다. Core 360개, 최신 구조의 홈·촬영·모델·저장 호환성 회귀 10개와 서명을 제외한 네이티브 Debug·Release 빌드가 통과했다. 해결 후 검사 범위와 실행 결과는 [#17 충돌 해결 검증](Validation/main17-conflict-resolution-2026-10-01.json)을 참고한다.
