# LiDAR 모듈 직접 테스트 안내

## 1. 실행 준비

- Xcode 프로젝트: `Dobby/Dobby.xcodeproj`
- Scheme: `Dobby`
- 최소 OS: iOS/iPadOS 26.4
- 실제 촬영: `ARWorldTrackingConfiguration.supportsFrameSemantics(.sceneDepth)`를 만족하는 LiDAR 기기.
- Xcode의 Signing & Capabilities에서 본인 Team을 선택한 뒤 연결한 기기로 실행한다.
- 시뮬레이터나 LiDAR 미지원 기기는 데모 실험을 사용할 수 있다. 미지원 기기에서 임의의 실제 치수를 만들어 반환하지 않는다.

## 2. 센서 없이 계산·화면 확인

앱의 **50cm 데모 실험**에서 조건을 선택하고 **데모 테스트 열기**를 누른다.

| 조건 | 확인할 결과 |
|---|---|
| 평면 | A/B를 이동하지 않았을 때 50.00cm |
| 기울기 | 25도 기울어진 가상 평면에서도 원래 A/B는 50.00cm |
| 잡음 | ±3mm 깊이 잡음과 일부 20cm 이상치가 섞인 데이터. 정답 50cm와 오차·상태를 비교 |
| 깊이 결손 | 숫자 대신 ‘측정 불가’와 깊이 부족 사유 |

노이즈·결손 데모도 실제 센서 촬영 결과가 아니다. 원래 점을 이동하거나 측정 항목을 바꾸면 50cm 정답 기준은 더 이상 해당하지 않을 수 있다. 줄자 기준값도 새 점에 맞게 수정한다.

## 3. 실제 LiDAR 측정

1. 우선 길이를 정확히 아는 평평한 물체를 준비한다. 그다음 펼친 옷으로 넘어간다.
2. **LiDAR 촬영 시작**을 누르고 카메라 접근을 허용한다.
3. 옷 전체와 두 끝점이 잘리지 않게 비춘다. 실시간 테두리가 옷을 둘러싸는지 확인하고, **깊이 확보 · 촬영 가능** 안내가 뜨는지 살핀다. 기울어진 평면도 계산할 수 있지만 가림·접힘·깊이 결손은 별도 문제다.
4. **촬영**을 누른 뒤 카메라를 잠시 유지한다. 첫 사용 가능한 후보부터 0.35초 동안 비교해 한 프레임의 원본 이미지와 깊이를 함께 고정한다. 4초 안에 안정된 추적·깊이를 확보하지 못하면 안내 후 재시도한다.
5. 옷 종류와 측정 항목을 먼저 선택한다. A, B를 순서대로 지정하거나 표시된 점을 끌어 위치를 조정한다.
6. 실제 줄자로 같은 끝점 사이를 재고 **줄자와 비교**에 cm 값을 입력한다.
7. 길이와 차이, A/B의 깊이·표본 수·계산 방법을 확인하고 물체 이름·기기·촬영 조건을 입력한다.
8. **테스트 기록 저장**을 누른다. 실패한 사례도 저장하면 깊이·좌표 문제를 재현할 수 있다.

| 항목 | 이 테스트 화면에서 사용할 점 |
|---|---|
| 두 점 사이 | 임의의 시작점 A와 끝점 B |
| 가슴 단면 | 같은 높이의 좌우 겨드랑이 기준점 |
| 어깨너비 | 좌우 어깨 봉제선의 합의된 기준점 |
| 총장 | 목 옆 기준점과 그 아래 밑단 기준점 |
| 소매길이 | 어깨 기준점과 소매 끝 기준점 사이 직선 |

의류 분류나 점 위치를 자동으로 추정하는 화면은 아니다. 이름을 선택하는 것만으로 점의 의미가 자동 검증되지는 않는다. 특히 래글런·드롭숄더는 팀이 합의한 측정 정의가 필요하다.

## 촬영 전 실시간 안내 확인

홈의 **실시간 안내 미리보기**에서 LiDAR 없이도 상태 전환을 시험할 수 있다. 합성 데이터로 같은 평가기와 안내 카드를 실행하며 실제 옷 인식 결과는 아니다.

| 카메라 표시 | 뜻과 다음 행동 |
|---|---|
| 흰색 · 옷 후보를 찾는 중 | 영상에서 전경을 찾지 못했다. 옷을 펼치고 배경과 구분되게 비춘다. |
| 주황색 · 여러 대상 / 끝부분 확인 / 너무 작음 | 주변 물건을 정리하거나 촬영 거리를 조정한다. |
| 주황색 · 깊이 부족 | 대상 내부 또는 가장자리에 쓸 수 있는 깊이가 부족하거나 센서 신뢰도가 낮다. 거리·각도를 조금 바꾼다. |
| 주황색 · 움직임 / 안정화 중 | 카메라를 잠시 멈추고 같은 옷을 유지한다. |
| 초록색 · 깊이 확보 · 촬영 가능 | 같은 후보에서 충분한 깊이가 연속으로 확보됐다. 테두리 안의 물체가 옷인지 확인하고 촬영한다. |

**영역 깊이 %**는 후보 마스크 안의 유효 깊이 비율이고, **가장자리 %**는 마스크 경계에서 중간 이상 신뢰도의 유효 깊이 비율이다. 의류 인식 확률이나 치수 정확도가 아니다. 화면 테두리는 후보를 둘러싼 사각형이며 옷 윤곽선·자동 측정점이 아니다.

현재는 Apple Vision의 일반 전경 분리를 사용한다. 가방·책 등도 후보가 될 수 있고, 배경과 비슷한 옷을 놓칠 수 있다. **의류 인식 성공**을 확정하는 기능은 이치의 의류 ML 연동 후 추가해야 한다. 안내가 부족해도 테스트 촬영은 할 수 있다.

실제 기기에서 아래를 확인한다.

1. 옷 한 벌을 펼치고 1~2초 유지했을 때 테두리와 상태가 맞는지 확인한다. 처리 속도에 따라 더 걸릴 수 있다.
2. 옷을 치우기, 물건 추가하기, 소매를 촬영 영역 밖으로 옮기기, 기기 움직이기에서 초록 표시가 해제되는지 확인한다.
3. 세로·가로 회전 후 테두리가 같은 후보 위에 있는지 확인한다.
4. 앱 전환·잠금·카메라 닫기 후 돌아왔을 때 이전 성공 표시가 남지 않는지 확인한다.
5. 어둡거나 반사되는 소재, 배경과 비슷한 옷에서 오탐·누락과 안내 지연을 기록한다.

## 4. 결과 해석

- **계산 완료:** 유효한 점·깊이·평면 표본으로 계산했다. 실제 오차가 0이라는 뜻은 아니다.
- **확인 필요:** 센서 신뢰도가 낮거나 없고, 여러 깊이 표면이 섞이거나 평면 대신 중앙값을 사용한 경우 등이다. 확정 치수로 사용하기 전 줄자로 비교한다.
- **측정 불가:** 깊이 부족, 미지정/가려진 점, 프레임 불일치, 잘못된 입력 등이 있다. 사유를 확인한다.

**주변 평면으로 깊이 안정화**를 끄면 주변 중앙값을 사용하는 기준선과 비교할 수 있다. 두 모드 모두 동일한 촬영 데이터로 계산한다. 평면 적합이 불가능한 곳에서는 켠 상태에서도 중앙값으로 대체되고 ‘확인 필요’가 표시될 수 있다.

이 모듈은 명시한 점 사이의 3D 직선 또는 구간 합을 계산한다. 접힌 옷을 폈을 때 길이나 주름을 따라간 표면 길이를 자동 복원하지 않는다.

## 5. 저장·공유·재현

- 기록은 앱 Documents의 `LiDARMeasurements/<기록 ID>/`에 저장된다.
- `measurement.json`: 원본 JPEG(base64), 깊이, 신뢰도, 보정값, 프레임 ID, 점, 정의, 결과, 옵션, 줄자 기준값. 새 촬영은 프레임 선택 기록과 지원 시 같은 프레임의 평활화 깊이를 함께 담는다.
- `summary.json`: 보관함에 표시할 요약. 두 파일을 모두 쓴 뒤 기록 폴더를 공개한다. 불완전 저장은 정상 기록으로 집계하지 않는다.
- 저장 후 **사진·깊이·측정점 JSON 공유**로 파일 앱/AirDrop 등에 전달한다.
- 홈의 가져오기 버튼에서 버전 1의 JSON을 선택하면 같은 프레임으로 다시 계산한다.
- 원본과 기록을 수정하면 기존 공유 링크 표시가 해제된다. 현재 상태를 공유하려면 다시 저장한다.
- 저장된 과거 결과와 현재 재계산 결과는 알고리즘 버전이 달라질 때 달라질 수 있다.

## 6. 실제 정확도 기록 방법

같은 물체·점·줄자 기준값으로 정면과 기울기, 가까움과 멀리, 밝고 어두운 소재를 각각 3회 이상 촬영한다. 거리 엔진 검증에서는 사람이 확인한 정확한 점을 사용한다. ML이 연결되면 같은 데이터에서 ML 점을 사용한 결과도 따로 비교한다.

개선 여부는 평균 오차만으로 정하지 않는다. 오차 상위 구간, 계속 길거나 짧게 나오는 편향, 측정 실패율과 반복 흔들림도 함께 기록한다. 실패 사례를 평가에서 빼지 않는다.

## 7. 자동 검증 범위

- Swift Package 테스트: 기하·입력 검증·좌표 변환·부분 실패·잡음·파일 보존·ML 계약·실시간 촬영 준비/만료 상태·의류 프리셋·기준선 보고서·프레임 선택·모델점 수동 확인 정책. 최신 개수와 결과는 [검증 기록](LiDAR-Validation.md)에 남긴다.
- 화면 테스트: 50cm 계산 → 저장 → 다시 열기, 깊이 결손 → 측정 불가, 실시간 안내 전환, 실측 보고서 빈 상태, 바지 프리셋 선택 시 점·정답 초기화, 자동 연결의 부분 성공·전체 저장·다시 열기, 최종 보고서의 합성 시도 제외. iPhone·iPad 각각 7개를 검증한다.
- 시뮬레이터/기기용 컴파일 검증.

이 검증은 계산과 앱 동작을 확인한다. 실제 센서 cm 오차는 실물 측정 기록으로 별도 검증한다.


## 8. 실측 비교 보고서

홈의 **실측 검증 → 비교 보고서**에서 실제 촬영·수동점 기록만 재계산한다. 같은 데이터에서 중앙값 방식과 평면 보정을 비교하며 합성 데모와 중복 저장은 별도로 센다. 실제 기록이 없으면 정확도 숫자를 보여주지 않는다.

옷 종류별 측정점 기준과 CSV 해석은 [실측 기준선 안내](LiDAR-Baseline-Protocol.md)를 참고한다. 측정 항목을 바꾸면 이전 점과 줄자 기준값은 초기화된다. 다른 길이의 정답을 실수로 재사용하지 않기 위한 동작이다.

새 보고서는 같은 촬영의 원본 깊이·평활화 깊이도 비교한다. 두 방식 모두 수치가 나온 공통 표본으로 오차를 계산하고, 한쪽 실패·평활화 자료 누락은 별도로 표시한다. 결과 화면의 **촬영 품질 기록**에는 후보 수·선택 대기시간·전체 화면 깊이 비율이 표시되며 실제 정확도를 뜻하지 않는다.

## 9. 자동 연결과 최종 보고서 확인

1. 홈의 **합성 자동 연결 테스트**를 누른다. 50.00cm·25.00cm 두 항목과 의도적으로 빠뜨린 점의 ‘측정 불가’가 함께 나와야 한다. 실제 옷·ML 추론 결과가 아니다.
2. 항목별 줄자값을 넣고 **전체 항목 기록 저장**을 누른다. 보관함에서 다시 열었을 때 모든 항목과 실패 사유, 입력한 기준값이 유지되는지 확인한다.
3. **이 사진에서 수동점 검증**은 같은 촬영에서 점 선택의 영향을 비교하는 기능이다. 모델 점을 수정하기 시작하면 나머지 점도 직접 확인해야 한다. 자동·수동 기록을 둘 다 저장한다.
4. 홈의 **최종 검증 · 시도 기록**에서 수동점/모델점 오차와 조건별 결과를 확인한다. 합성 자료만 있으면 실물 정확도는 빈 상태여야 한다. 합성 자동 실행도 실기기 시도 횟수에 포함되지 않는다.
5. 검증 CSV·검증 Markdown·시도 CSV를 각각 내보낼 수 있다. 시도 기록은 사진이 없는 촬영 실패·시간 초과·취소도 담는다. 수동은 촬영까지, 자동은 촬영부터 계산까지를 기록하므로 처리시간을 같은 의미로 비교하지 않는다.

실제 학습된 모델이 없는 기본 앱에서는 자동 촬영 버튼이 **모델 연결 대기**다. 현재 기기에서 실제 센서 거리 계산을 시험하려면 3절의 수동 A/B 검증을 이용한다. 메이슨·이치의 연결 지점과 실기기 인수 조건은 [인수·연결 안내](LiDAR-Handoff.md)에 있다.
