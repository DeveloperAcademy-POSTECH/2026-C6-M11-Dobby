# iPhone 17 Pro 실측 기준선 수집

작성일: 2026-09-25 · 갱신일: 2026-09-27 · 알고리즘: `lidar-unprojection-1.0.1`

## 현재 완료 범위

촬영·수동 측정점·줄자 비교·원본 저장·재계산·실측 보고서·CSV 내보내기를 준비했다. 사용자가 지금 실측하기 어렵다고 알려 실제 오차 측정은 보류 중이다. 소프트웨어 테스트 결과를 센서 정확도나 모든 옷의 자동 인식 성능으로 해석하지 않는다.

## 먼저 사용할 측정 항목

| 옷 종류 | 앱의 수동 측정 프리셋 |
|---|---|
| 상의·아우터 | 가슴 단면, 어깨너비, 총장, 소매길이 |
| 바지 | 허리·엉덩이·허벅지·바짓단 단면, 앞밑위·인심·바깥길이 직선 |
| 치마 | 허리·엉덩이 단면, 치마 길이·밑단 폭 직선 |
| 원피스 | 가슴·허리 단면, 어깨너비, 소매길이, 총장·밑단 폭 직선 |
| 기타 또는 특수 형태 | 직접 지정한 두 점 사이 |

모든 프리셋은 A/B 두 점의 3D 직선거리다. 단면을 자동으로 두 배 하여 둘레로 취급하지 않는다. 봉제선을 따라 휘어진 밑위·인심이나 주름을 따라간 길이는 별도 방식이 필요하다. 어깨선이 없는 옷, 비대칭 형태는 같은 기준점과 펼침 상태를 기록한다. 의류 종류를 선택해도 측정점이 자동으로 검출되지는 않는다.

## 실측 가능해졌을 때 진행 순서

1. 먼저 길이를 확인한 평평한 물체로 촬영·좌표 정합을 확인한다. 그다음 대표적인 상의와 바지부터 옷 종류를 넓힌다.
2. iPhone 17 Pro에 앱을 설치하고 **LiDAR 촬영 시작**으로 옷 전체를 비춘다. 초록 표시는 후보 깊이 확보이며 의류 인식 확정이 아니다.
3. 촬영 후 옷 종류와 측정 항목을 선택하고, 줄자로 확인할 위치와 정확히 같은 두 점을 지정한다.
4. **줄자와 비교**에 실제 길이(cm), 옷·물체 이름, 기기 모델과 촬영 조건을 입력한다. 기기 칸에는 기본적으로 기기의 하드웨어 식별자가 들어간다. 알아보기 쉬운 이름으로 바꿔도 된다.
5. 정상·확인 필요·측정 불가 모두 저장한다. 실패를 기록에서 빼면 성공률이 부풀려진다.
6. 같은 조건에서 새 사진을 3회 이상 촬영한다. 한 사진의 점을 수정해 여러 번 저장한 것은 독립 촬영이 아니다.
7. 홈의 **실측 검증 → 비교 보고서**를 연다. 숫자가 없다면 아직 실제 정확도를 계산할 자료가 없는 것이다.
8. **비교 기록 CSV 공유**로 자료를 내보낸다. 개별 사진·깊이가 필요하면 측정 화면의 JSON 공유도 함께 사용한다.

첫 예비 조건은 정면·약한 기울기, 옷 전체가 들어오는 두 거리다. 이후 로드맵의 거리·각도·소재 평가로 확대한다. 초기부터 지원 가능 거리나 오차를 단정하지 않는다.

## 보고서 해석

두 방법은 같은 촬영·점·설정으로 계산하되 `useLocalPlane`만 바꾼다.

- **기본:** 이상치 제거 후 주변 깊이 중앙값. 평면 보정 없이 추정하므로 정책상 ‘확인 필요’가 될 수 있다.
- **깊이 안정화:** 평면에 맞는 주변 표본이 있을 때 원래 끝점의 깊이를 추정한다.
- **수치 산출:** 계산 완료 + 확인 필요. 품질 기준을 충족한 비율과는 다르다.
- **평균 절대오차:** 앱 치수와 줄자 치수의 차이를 양수로 바꿔 평균한 값.
- **P95:** 절대오차를 정렬했을 때 95% 지점의 값. 표본이 적으면 특히 조심해서 해석한다.
- **평균 편향:** 앱 치수 − 줄자 치수. 양수면 길게, 음수면 짧게 측정하는 경향.

오차는 유효한 줄자값과 계산된 수치가 모두 있는 기록으로만 계산한다. 확인 필요 수치도 포함한다. 실패·기준값 누락 수를 함께 보며, 성공 사례의 평균만으로 성능을 판단하지 않는다.

보고서는 저장 당시 숫자를 믿고 집계하지 않고 현재 엔진으로 다시 계산한다. 같은 프레임·항목의 중복 저장은 가장 최신 편집 한 건만 사용한다. 합성 데이터, 수동점 이외의 입력, 해석 불가능한 파일은 별도 제외 수로 표시한다. 한 파일에 여러 항목이 들어 있으면 단일 줄자값을 어느 항목에 적용할지 모호하므로 현재 기준선 집계에서 제외한다.

현재 화면의 통계는 기기·소재·조건을 합친 탐색용 집계다. CSV의 조건별 필터로 같은 조건을 비교하고, 최종 지원 범위와 정확도는 충분한 독립 촬영 기록을 확보한 후 정한다.

## 원본 깊이와 평활화 깊이 비교

새 버전은 촬영 시 짧은 후보 구간에서 한 프레임을 선택한다. 결과 화면의 **촬영 품질 기록**을 펼치면 후보 수, 선택 대기시간, 전체 화면 깊이 비율과 움직임 정보 유무를 볼 수 있다. 이 비율은 옷 인식률이 아니다.

지원 시 원본 깊이와 평활화 깊이를 같은 촬영에 함께 저장한다. 사용자가 별도로 두 번 촬영하거나 두 세트의 점을 지정할 필요는 없다. **비교 보고서**의 추가 표에서 같은 A/B점과 동일한 평면 보정 설정으로 두 출처를 비교한다.

- **동일 프레임 쌍:** 프레임 ID·시각·보정 정보가 같은 기록만 사용한다. 이전 기록에 평활화 깊이가 없으면 ‘누락’, 잘못 연결된 자료는 ‘불일치’로 구분한다.
- **시도 수와 실패:** 양쪽의 전체 시도 분모는 같다. 한쪽에서만 치수가 나오면 다른 쪽은 실패로 남긴다.
- **오차 비교 수:** 양쪽에서 모두 치수가 나오고 줄자값도 있는 같은 기록만 MAE·P95·편향에 사용한다. 이는 양쪽 성공 표본의 비교이므로 반드시 실패율도 함께 본다.
- **기본 계산·평면 보정 표:** 기존 표도 유지한다. 여기서는 깊이 출처를 고정하고 평면 보정 적용 여부만 바꾼다.
- **CSV:** 기존 열 뒤에 평활화 쌍 상태, 측정값·실패 이유, 공통 오차 비교 대상 여부와 양쪽 오차를 추가한다. 누락된 숫자를 0으로 채우지 않는다.

평활화는 과거 프레임 정보를 섞어 흔들림을 줄이는 기능이다. 더 매끈해 보인다고 실제 치수가 더 정확하다는 뜻은 아니다. 지금은 원본 깊이를 기본으로 유지하며 채택 여부는 실측 후 결정한다.

프레임 선택 전후 정확도·성공률 비교는 아직 하지 않았다. 선택된 한 프레임만 저장하므로 이 기록만으로 모든 탈락 후보보다 실제 오차가 작았다고 증명할 수 없다. 실기기에서 먼저 촬영 대기시간과 성공·실패 횟수, 반복 치수 편차를 확인한다. 촬영 자체가 실패해 저장할 사진이 없는 경우도 별도 시험 기록에 남긴다.
