# 하의 인식 모델 연결 · 2026-09-28

## 이번에 만든 것

사용자가 제공한 `ClothesML/하의_ML/BottomLandmarks.mlpackage`를 Dobby에 포함하고, **사진 → 하의 측정점 → 같은 프레임의 LiDAR 치수**로 연결했다. 제공받은 학습 가중치를 그대로 사용했으며 이번 작업에서 새 학습을 수행한 것은 아니다. 원본 폴더와 `bottom7.pt`는 수정하지 않았다.

지원 대상은 **펼친 바지·반바지 한 벌**이다. 치마·상의·착용 사진·겹쳐 놓은 여러 벌의 인식은 지원 범위로 보지 않는다. 허리는 위, 밑단은 아래로 놓고 옷 전체를 촬영한다.

## 직접 테스트

1. `Dobby/Dobby.xcodeproj`의 Dobby를 실행한다.
2. LiDAR 없이 확인하려면 **하의 사진으로 인식 테스트 → 하의 사진 선택**을 누른다. 실제 모델이 찾은 점과 연결선을 사진 위에 표시한다. 이 경로는 깊이가 없으므로 cm를 계산하거나 실측 기록을 만들지 않는다.
3. iPhone 17 Pro에서는 **하의 자동 측정 촬영 → 촬영**을 누른다. 촬영된 한 프레임의 RGB에서 점을 찾고 같은 프레임의 깊이로 치수를 계산한다.
4. 결과에서 각 항목의 실패 사유·신뢰도를 확인한다. **이 사진에서 수동점 검증**으로 위치를 비교할 수 있다. 줄자 기준값을 입력하고 전체 항목을 저장하면 기존 검증 보고서에 모델 출처로 구분된다.

주황색 점은 모델 신뢰도 50% 미만이다. 기본 거리 엔진은 이 점에 의존하는 항목을 낮은 모델 신뢰도로 실패 처리하며, 다른 항목은 유지한다. 신뢰도 수치는 실제 위치가 맞을 확률이나 cm 오차 보증이 아니다. 촬영 중에는 하의 모델의 점과 같은 RGB의 Vision 마스크를 대조한다. 일치한 옷은 파란 실루엣으로 표시하고, 깊이·안정성까지 충족하면 새 실측 촬영 화면의 셔터가 활성화된다. [촬영 화면 안내](Garment-Capture-Flow.md)를 참고한다.

## 점과 측정 항목

좌우는 **모델에 넣는 정방향 사진에서 보이는 좌우**이며 착용자 기준이 아니다. 원본 센서 이미지로 좌표를 돌려도 의미 ID는 유지한다.

| 점 | 의미 |
|---|---|
| waist_left / waist_right | 허리 양 끝 |
| crotch | 가랑이 |
| hem_left_outer / hem_left_inner | 화면 왼쪽 다리 밑단 바깥 / 안쪽 |
| hem_right_inner / hem_right_outer | 화면 오른쪽 다리 밑단 안쪽 / 바깥 |
| waist_center | 허리 양 끝을 3D로 복원한 뒤 구한 중점. 깊이 없는 사진 테스트에서는 2D 평균을 표시용으로만 사용 |

`schema_bottom7.json`의 keypoints 순서·derived·skeleton을 읽는다. 모델의 7개 점과 파생 중점으로 허리 단면, 밑위, 좌우 총장·밑단 단면·인심 **8개 직선 항목**을 생성한다. 둘레나 곡선 봉제선 길이가 아니다. LiDAR 측정에서는 허리 양 끝의 3D 좌표를 평균하고, 그 위치에서 가랑이까지의 거리를 계산한다. 화면에는 이 3D 중점을 다시 사진 좌표로 옮겨 표시한다. 계산 방식의 원근 오류는 수정했지만 밑위의 실물 정확도는 별도로 검증해야 한다.

## 처리 구조

- `Core/BottomLandmarkDecoder.swift`: 스키마·연결선 검증, 정수 크기의 레터박스 좌표 역변환, 네 방향 회전 복원, 출력 후보 해석. Foundation만 사용한다.
- `Core/MeasurementEngine.swift`: 파생점의 `derivedFrom` 원본 ID를 따라 깊이를 해석한 뒤 3D 평균을 계산한다. 누락·낮은 신뢰도·가림·깊이 실패를 보존하며, 해당 점을 쓰는 항목만 실패 처리한다.
- `Core/ResolvedLandmarkCoordinates.swift`: 깊이가 있는 결과의 3D 중점을 재투영해 표시한다. 계산에 실패한 파생점은 잘못된 2D 중점으로 대신 표시하지 않는다.
- `Capture/CoreMLBottomLandmarkProvider.swift`: 모델을 한 번 로드해 재사용하는 actor. 이미지 처리와 추론은 메인 화면 작업과 분리한다. 사진 프레임 크기와 sessionID/frameID를 보존하며 `GarmentLandmarkProviding` 계약으로 연결한다.
- `UI/BottomRecognitionView.swift`: 사진 선택·로딩·오류·표시 상태를 관리한다. ViewModel을 추가하지 않았다.
- `Models/BottomLandmarks.mlpackage`, `Models/schema_bottom7.json`: 제공 파일을 복사한 앱 리소스. Xcode 빌드 시 모델을 컴파일한다.

실제 모델 입출력은 `image` RGB 640×640 → `var_1345` Float32 `[1,26,8400]`이다. 입력은 비율을 유지해 정수 크기로 줄이고 남는 영역을 RGB(114,114,114)로 채운다. 출력에서 여백·실제 가로세로 축척·회전을 되돌려 **전체 원본 RGB의 [0,1) 좌표**를 반환한다. Core ML tensor의 stride를 존중한다.

객체 점수 0.25는 제공 모델 설명을 따른다. 중복 후보는 IoU 0.45로 제거하고 독립 후보가 여러 개 남으면 한 벌을 다시 촬영하도록 안내한다. 이 필터가 심하게 겹친 의류까지 구분한다고 보장하지 않는다. 사진 밖의 점을 경계에 강제로 붙이지 않고 누락 처리하며, 관련 치수만 실패하게 한다. 모델 자체에는 마스크 출력이 없으므로 촬영된 동일 JPEG에 Vision 전경 분할을 적용하고, 인식점과 일치하는 단일 마스크를 `GarmentLandmarkSet.mask`로 전달한다. 사진만 불러오는 인식 화면은 기존 점 표시 기능을 유지한다.

## 확인한 것과 남은 검증

- 실제 하의 사진 3장으로 제공 Core ML 모델 및 앱의 동일 provider 경로를 실행했다. 7개 원본점과 1개 파생점이 출력되며 좌표·신뢰도를 확인했다.
- 반바지 예시는 객체 점수 약 0.937, 원본 7점 점수 0.948~0.999였다.
- 긴바지 예시는 객체 점수 약 0.923이지만 한 허리점 점수가 약 0.433이었다.
- 옆으로 놓인 데님 예시는 객체 점수 약 0.495, 밑단점 점수 약 0.070~0.116이었다. 객체 점수만으로 측정 가능을 선언하지 않는다.
- 실제 반바지 사진의 픽셀을 역회전한 뒤 프레임 방향을 right/down/left로 지정해 같은 모델로 추론했다. 표시 좌표로 다시 옮겼을 때 최대 차이는 약 0.000391(640 입력 기준 약 0.25px)로, 허용한 2/640 이내였다. 이는 회전 처리의 일관성 시험이다. [실행 JSON](Validation/bottom-provider-2026-09-28.json)에 원본 경로·점·신뢰도·프레임 확인 결과를 남겼다.
- 이 사진들에는 검증 가능한 랜드마크 정답과 줄자 치수가 없으므로 위 실행 결과를 정확도 평가나 cm 오차로 해석하지 않는다.
- 제공 README의 학습 데이터 645장 및 시험 60장 수치는 이번에 재검증하지 못했다. 해당 학습/라벨링 경로는 이 기기에 없고 기존 ClothesML 사진 manifest에는 점 정답이 없다.
- 실제 iPhone 17 Pro 촬영·발열·지연·소재별 cm 정확도는 사용자 실측을 기다린다. Mac 추론 시간은 iPhone 성능 근거가 아니다.

추가 학습은 이미지별 7점 정답, 누락·가림 표시, 의류별 중복 없는 train/validation/test 구분이 준비된 뒤 진행한다. 모델 자신의 예측을 검증된 정답으로 사용하지 않는다.

## 코드 리뷰 후 수정한 밑위 계산 (9/29)

이전 구현의 `waist_center`는 2D 이미지 좌표의 평균이었다. 허리 양 끝의 깊이가 다른 촬영에서는 실제 3D 중점과 달라 밑위에 오차가 생겼다. 정확한 측정점과 잡음 없는 45° 합성 평면(허리 60cm, 허리 중심 깊이 60cm)에서 밑위 정답 30cm가 **31.82cm, valid**로 계산되는 것을 재현했다. 이는 실제 기기에서 측정한 오차가 아니라 계산 방식의 오류를 확인한 것이다.

수정된 `lidar-unprojection-1.0.2`는 허리 양 끝을 먼저 3D로 복원해 중점을 만든다. 파생점 위치의 깊이를 다시 읽지 않으며, 원본점의 품질과 불확실성을 이어받는다. 사진만 보는 테스트 화면의 2D 중점은 그대로 표시용 힌트이며 cm 계산에 사용하지 않는다.

저장 시 `derivedFrom`과 결과의 `sourceLandmarkIDs`, `spatialAverage` 방법을 남긴다. 현재 앱은 이 선택 필드가 없는 과거 기록도 읽는다. 정확히 `bottom7-976144d4d652` 모델에서 생성한 옛 허리 중점은 재계산 시 같은 3D 방식으로 해석하고, 원본 허리점이 저장되지 않은 옛 기록은 해당 항목을 계산 불가로 처리한다. 새 결과에 추가된 `spatialAverage`를 모르는 구버전 앱이 새 기록을 읽는 것은 보장하지 않는다.

수동점 비교로 전환할 때는 원본 허리점까지 유지해 동일한 계산을 보여준다. 사용자가 첫 점을 직접 지정하면 파생 관계를 제거하고 두 끝점을 다시 확인하도록 한다. 저장·다시 열기·수동 보정에서 2D 중점 계산으로 돌아가지 않도록 회귀 테스트를 추가했다. 합성 기하 테스트 통과는 모델 검출률이나 실제 센서 cm 정확도의 보증이 아니다.
