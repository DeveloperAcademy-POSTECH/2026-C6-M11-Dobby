# 상의 인식·촬영 흐름 개선 · 2026-09-30

## 확인한 문제

iPhone 17 Pro에서 수집한 최근 시도 기록 5건 중 2건은 사진 촬영 후 `unmatchedGarment`로 실패했다. 사진을 확보하지 못한 오류가 아니라, 모델의 측정점과 Vision 윤곽을 연결하지 못한 오류다. 실패한 사진과 점은 시도 기록에 없으므로 사용자의 실패 원인을 옷 방향으로 단정할 수 없다.

| 기존 실기기 시도 | 촬영 | 측정점·윤곽 | 전체 |
|---|---:|---:|---:|
| 첫 부분 결과 | 0.390초 | 3.299초 | 3.698초 |
| 이후 부분 결과 1 | 0.400초 | 0.111초 | 0.521초 |
| 이후 부분 결과 2 | 0.388초 | 0.108초 | 0.506초 |
| 점·윤곽 불일치 1 | 0.393초 | 0.067초 | 0.460초 |
| 점·윤곽 불일치 2 | 0.379초 | 0.073초 | 0.452초 |

시도 로그에는 옷 종류가 없어 위 기록을 종류별 속도 통계로 해석하지 않는다. 첫 처리의 긴 대기는 모델 준비·앞선 실시간 분석과 관련될 수 있지만, 로그만으로 각 비용을 분리할 수 없다.

로컬 반팔 10장·긴팔 10장을 검사하니 기존 기본 방향에서는 긴팔 5장이 실패했다. 해당 5장은 목선이 사진 아래에 있는 옷이었고, 동일 사진을 180도 돌려 분석하면 모두 점과 윤곽이 연결됐다. 이 관찰은 독립 평가셋의 인식률이나 점 위치 정확도 검증이 아니다.

## 인식과 측정점 처리

상의의 실시간·촬영 후 분석에 같은 `recognizeForeground` 경로를 사용한다.

1. 기본 방향에서 모델 점과 윤곽을 엄격하게 연결한다.
2. 미검출 또는 점·윤곽 불일치일 때만 180도 방향으로 한 번 재시도한다.
3. 두 방향 모두 엄격한 연결에 실패하면, 이미 생성한 마스크에서 충분한 몸통 증거가 있는 상의만 부분 결과로 처리한다.

기본 방향이 성공하면 유지한다. 방향별 점수를 비교해서 높은 점수의 결과로 교체하지 않는다. 모델 추론은 최대 2회이며 부분 연결 때문에 Vision을 다시 실행하지 않는다.

부분 연결에는 6개 이상의 직접점, 신뢰도 0.7 이상의 양쪽 몸통 상단과 양쪽 밑단, 충분한 공간 분포가 필요하다. 여러 옷·여러 전경·잘못된 좌표·취소를 이 경로로 우회하지 않는다. 하의의 기존 엄격한 연결 정책도 유지한다.

윤곽과 연결되지 않는 상의 점은 표시·계산 불가로 처리한다. 좌표를 임의로 윤곽에 붙이거나 신뢰도를 올리지 않는다. 해당 점을 쓰는 치수만 계산 불가가 되고, 독립적으로 계산할 수 있는 치수는 남는다. 파생점도 원래 입력점의 불가 상태를 이어받는다.

재시도한 점과 윤곽은 같은 방향에서 분석한 뒤 원본 RGB 좌표로 되돌린다. 카메라의 실제 방향, 촬영 프레임 ID, 원본 사진과 깊이는 그대로 보관한다. 이전 실시간 프레임의 점·마스크를 촬영 사진에 붙이지 않는다.

## 속도와 카메라 상태

- 첫 실시간 인식 전에 Core ML의 실제 첫 예측과 Vision 첫 요청을 한 번 준비한다. 화면에는 **옷 인식 모델을 준비하고 있어요**를 표시한다. 준비용 중립 이미지 결과는 인식·실측 결과로 쓰지 않는다.
- 실시간 RGB 복사를 최대 960px로 제한한다. 전체 화각과 정확한 비율은 유지하고, 촬영용 원본 RGB와 깊이는 유지한다.
- RGB를 복사한 뒤 ARKit 이미지 버퍼를 비동기 모델 분석 동안 보유하지 않는다. 물리적인 실시간 작업은 최대 1개다.
- YOLO 텐서의 8,400개 anchor를 읽을 때 반복하던 NSNumber 생성을 제거했다. 실제 메모리 strides와 버퍼 범위를 검사하며 Float16·Float32·Double을 지원한다.
- 실시간 분석 간격을 0.6초에서 0.35초로 줄였다. 2초 freshness 제한과 연속 안정 관찰 조건은 유지한다.
- 셔터를 누르면 새 실시간 분석을 중지해 촬영 프레임 분석 앞에 작업이 쌓이지 않게 한다. 촬영 실패·취소는 실시간 분석을 복구한다.
- 같은 화면에서 재촬영하면 ARKit 추적을 재사용한다. 화면 이탈·백그라운드에서는 세션을 종료한다.

Mac의 부분 벤치마크에서 텐서 해석 평균은 **2.915ms → 0.671ms**였다. 전체 앱이 4배 빨라졌다는 의미가 아니다. 이 수치는 확대·중립 여백을 넣은 사진과 Mac의 debug 실행 기준이며 iPhone 처리 속도를 대신하지 않는다. 근거: [capture-performance-2026-09-30.json](Validation/capture-performance-2026-09-30.json).

## 촬영과 결과 화면

- 사진을 확보하면 해당 사진을 즉시 전달해 고정 화면을 만든다. **사진 → 측정점 → 길이** 진행 상태를 표시한다.
- 표시용 JPEG 디코딩은 UI actor 밖에서 수행하고 이미지 크기를 제한한다. 보관하는 원본과 정규화 좌표는 유지한다.
- 촬영 실패·측정점 실패·길이 계산 실패를 구분한다. 점 인식 실패를 옷이 잘렸다는 오류로 안내하지 않는다.
- 촬영 후 인식이 실패해도 **사진에서 측정점 확인**으로 같은 사진의 수동 측정을 열 수 있다.
- 결과의 확인 필요·측정 불가 항목에는 **이 사진에서 측정점 직접 확인** 버튼을 표시한다.
- **측정점 확인·수정** 메뉴에서는 자동값이 있는 항목도 바로 두 점을 확인할 수 있다. 높은 모델 신뢰도로 잘못 놓인 점을 직접 검토할 수 있도록 열어 둔다.
- 확인 필요 값만 있는 결과를 자동 실측 완료라고 표시하지 않는다.
- 수동 확인은 별도 기록이다. 자동 값을 덮어쓰지 않으며, 목선 기준 총장의 두 점을 편집하면 기존 규칙대로 별도의 수동 직선 측정으로 전환한다.

## 검증

- Core 회귀 테스트 **312개 통과**, 실패 0. 방향 재시도 우선순위·최대 횟수, 부분 결과의 치수별 전파, 취소된 snapshot 억제, 텐서의 3가지 dtype × 3가지 메모리 배치, 비율·좌표 보존 포함.
- 로컬 사진 20장 모두 실시간·촬영 adapter에서 연결 성공. 두 경로의 좌표·신뢰도·표시 가능 여부와 마스크가 일치했다. 4방향 raw 회전의 마스크 IoU는 1.0이었다.
- 별도 사진 인식 테스트는 순수 pose 후보점 경로다. 20장 중 19장은 11개 직접점을 반환했고, `tops_T25.jpg`는 기본 방향에서 일부 점이 이미지 밖으로 나가 8개만 반환했다. 이 경로는 윤곽 불일치 재시도를 하지 않는다. 해당 사진도 실제 촬영·실시간의 결합 경로에서는 180도 재시도로 회복했다. 보고서의 `requiredChecksPassed=false`는 이 완전성 검사이며, `foregroundChecksPassed=true`와 구분한다.
- 상의 사진 20장의 연결 보고서: [top-recovery-2026-09-30.json](Validation/top-recovery-2026-09-30.json).
- 하의 3장의 원래 측정점·검출 점수·4방향 결과와 기존 실패 경로가 유지됐다. 하의의 검정·회색 빈 사진 pose 오검출도 기존과 같지만, 촬영 adapter는 세 종류의 빈 사진을 모두 거부한다. 하의 3장 중 2장은 기존에도 윤곽 연결에 실패했으므로 전체 하의 인식 성공이라고 보고하지 않는다. 비교: [bottom-regression-2026-09-30.json](Validation/bottom-regression-2026-09-30.json).
- iPhone 17 Pro / iOS 26.4 시뮬레이터의 서로 다른 UI 테스트 **9개 통과**. 기존 촬영·상의 6개 치수·재촬영·저장 재열기·부분 결과와 새 직접 수동 확인 버튼, 기존 하의 사진·라이브 안내·합성 결과 재열기를 확인했다. 초기 새 버튼 식별자 오류를 수정한 뒤 해당 테스트와 하의 3개를 다시 실행했다.
- 최종 iOS 기기용 빌드 성공. `CODE_SIGNING_ALLOWED=NO`이며 실제 기기 설치·개선 후 카메라 촬영 결과는 아니다.

## iPhone에서 다시 확인할 항목

최신 소스로 빌드해 **실측 촬영**을 연다. 2026-10-01부터 종류는 자동 판별하므로 상의를 선택할 필요가 없다. [자동 판별 안내](Automatic-Garment-Recognition.md)를 참고한다. 같은 반팔·긴팔을 정상 방향과 180도 방향으로 각각 촬영하고, 윤곽이 나타나는 대기와 촬영 후 진행 화면을 확인한다. 불가 항목은 결과에서 바로 두 점을 확인한다.

점의 의미가 실제 목옆·어깨·겨드랑이·소매끝인지 눈으로 확인하고 같은 기준으로 줄자와 비교한다. 높은 모델 신뢰도나 윤곽 연결 성공은 점 위치·cm 정확도를 보증하지 않는다. 이번 변경은 모델 가중치를 재학습하지 않았다. 기본 방향에서 높은 신뢰도로 잘못 놓인 점은 여전히 학습 데이터와 모델 개선이 필요하다.

현재 소매길이는 두 점 사이 직선거리다. 굽은 소매나 주름을 펼친 원단 길이를 자동 복원하지 않는다. 실제 개선 후 iPhone의 인식률·반복 촬영 지연·줄자 오차는 별도로 측정해야 한다.

2026-10-01의 표시 전용 후속 변경은 [윤곽 표시·애니메이션 개선](Garment-Silhouette-Presentation.md)에 정리했다. 사선 경계와 전환을 다듬으며 측정에 쓰는 마스크·점·깊이는 유지한다.
