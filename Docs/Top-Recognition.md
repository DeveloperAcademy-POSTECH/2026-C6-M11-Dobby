# 상의 모델 연결 · 2026-09-30

실기기 피드백에 따른 최신 변경과 검증은 [상의 인식·촬영 흐름 개선](Garment-Recognition-Improvements.md)에 정리했다. 아래 확인 결과는 최초 모델 연결 시점의 기록이다.

## 실행 방법

현재 실행 방법은 **홈 → 옷 촬영 · 실측 → 실측 촬영**이다. 촬영 전에 종류를 선택하지 않고 앱이 상의·하의를 판별한다. 자동 판별은 2026-10-01에 추가했으며 [상·하의 자동 판별](Automatic-Garment-Recognition.md)에 정리했다.

- **실측 촬영**: 펼친 옷을 인식하고 실제 윤곽을 표시한 뒤, 같은 RGB/깊이 프레임에서 cm 치수를 계산한다. LiDAR 지원 기기가 필요하다.
- **모델별 사진 진단 → 상의 사진 인식 진단**: 사진 위에 측정 후보점과 모델 신뢰도를 표시한다. 일반 사진에는 깊이가 없으므로 cm를 계산하지 않는다.
- **촬영 화면 미리보기**: `--garment-preview-top` 실행 인자로 합성 상의·합성 깊이로 인식 전/후, 결과, 재촬영, 저장을 확인한다. 실제 모델이나 센서 정확도 검증은 아니다.

최초 연결 시에는 촬영 전에 종류를 선택했다. 현재는 전달본의 별도 15종 분류기를 연결해 해당 측정점 모델을 선택한다. 두 pose 모델의 점수를 서로 비교하지 않는다. 치마 실측은 지원하지 않는다.

## 모델과 좌표

원본은 `Challenge 6/ClothesML/상의_ML/GarmentPipelineHandoff/Resources`이다. 앱에는 원본과 바이트가 같은 `TopLandmarks.mlpackage`, `schema_top.json`을 추가했다.

- 모델 버전: `top11-ec1e6b054d59`
- weights SHA256: `ec1e6b054d59df095cd704a41f71d96fdb43ccdf37a7bd7b5a2fc7a07af04868`
- 입력: RGB 640×640, 비율 유지 letterbox, 회색 114 패딩.
- 출력: Float32 `[1, 38, 8400]`.
- 직접 예측: 목옆·어깨·겨드랑이·소매끝 좌우, 밑단 좌/중앙/우 11점.
- 파생점: `neck_center`; 목 양끝을 각각 깊이로 복원한 뒤 3D에서 평균한다.

기존 하의의 직렬 추론 어댑터를 재사용한다. 이미지 방향을 한 번 적용하고 실제 패딩 크기로 역변환해 원본 raw RGB 좌표를 복원한다. 촬영 프레임의 session/frame ID를 그대로 유지하며, 다른 프레임의 깊이나 실시간 마스크를 사용하지 않는다.

Vision의 윤곽 분할도 같은 upright 방향에서 수행한다. 방향을 바꿔 촬영하면 마스크는 보간 없는 90도 정수 픽셀 변환으로 raw RGB/깊이 좌표에 되돌린다. 이 과정에서 경계·구멍·면적을 보존한다.

## 실측 항목

스키마의 `skeleton`은 윤곽 표시용 연결선이다. 이를 실측 항목으로 사용하지 않는다.

| 저장 ID | 항목 | 측정점 |
|---|---|---|
| `top.shoulderWidth` | 어깨너비 | `shoulder_left` ↔ `shoulder_right` |
| `top.chestWidth` | 가슴 단면 | `armpit_left` ↔ `armpit_right` |
| `top.hemWidth` | 밑단 단면 | `hem_left` ↔ `hem_right` |
| `top.sleeveLengthLeft` | 왼쪽 소매길이(직선) | `shoulder_left` ↔ `sleeve_end_left` |
| `top.sleeveLengthRight` | 오른쪽 소매길이(직선) | `shoulder_right` ↔ `sleeve_end_right` |
| `top.totalLength` | 총장(목선에 수직) | `neck_center` ↔ `hem_center`, 목 양끝의 가로축 성분 제외 |

총장은 카메라의 x나 화면의 y를 고정해 계산하지 않는다. 3D 목 양끝으로 단위 가로축 `u`를 구하고, 목 중앙에서 밑단 중앙까지의 벡터 `d`에 대해 `d - dot(d, u) * u`의 길이를 사용한다. 이 규칙은 같은 물리 좌표에 대한 회전·이동에 불변이며, 잘못 인식된 목선이나 비대칭 목선은 결과에도 영향을 준다.

투영은 모든 측정점을 깊이로 복원한 후 수행한다. 투영 끝점은 3D에서 다시 이미지로 투영하여 측정선에 표시한다. 원래 밑단 예측 좌표는 기록에 유지한다. 기준축이 없거나 신뢰도가 낮거나 방향을 정의할 수 없으면 총장만 계산 불가로 표시한다.

## 저장과 수동 검증

저장 데이터에 `MeasurementDefinition.projection`과 기준축 ID를 함께 보관한다. 필드가 없는 기존 기록은 기존 직선 계산을 유지한다. 알고리즘 버전은 `lidar-unprojection-1.1.0`이다.

총장을 수동 검증 화면에서 열면 목 양끝의 지원점까지 유지해 같은 규칙으로 재계산한다. 두 끝점을 직접 수정하기 시작하면, 2점 편집기가 목 가로축을 함께 확정할 수 없으므로 별도 **수동 직선** 측정으로 전환한다. 저장 ID는 `top.totalLength.manualStraight`로 바뀌고 기준값은 비운다. 자동 총장과 의미가 다른 값을 같은 항목의 비교 통계에 섞지 않는다.

## 촬영 기준과 남은 실기기 검증

옷과 소매를 바닥에 평평하게 펼친다. 옷걸이 사진과 접힌 소매는 학습 조건과 다르며, 민소매에서는 소매끝 점을 사용할 수 없다. 높은 모델 신뢰도만으로 점의 위치나 실제 cm 오차가 작다고 판단할 수 없다.

소매값은 어깨와 소매끝 사이의 직선거리다. 굽은 소매나 주름의 원래 원단 길이, 봉제선을 따라간 길이를 복원하지 않는다. 결과의 점 위치를 확인하고 줄자와 같은 측정 기준으로 비교해야 한다.

Mac에서의 실제 모델 추론, 좌표 회전·마스크 정합 검증, 합성 기하 회귀와 시뮬레이터 화면 검증은 실제 iPhone의 센서 정확도와 구분한다. iPhone 17 Pro에서 카메라/깊이 정합, 반복 촬영 응답성, 줄자 대비 항목별 오차를 별도로 확인해야 한다.
