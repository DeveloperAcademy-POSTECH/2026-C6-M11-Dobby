# 옷 인식 · 실측 촬영 화면

## 실행

앱 홈에서 **옷 촬영 · 실측**을 누르면 카메라가 열린다. 옷 종류를 선택할 필요는 없으며, 윤곽이 인식되어 셔터 가운데 주황색 점이 나타나면 촬영할 수 있다. 상의·하의 종류와 측정점은 촬영한 사진에서 판별한다. Debug의 **측정 실험실**은 기존 검증 도구를 별도로 연다.

홈과 **보관함**은 같은 SwiftData 상품 저장소를 사용한다. 보관함에서 상품을 다시 열어 정보를 수정하거나 내보내기를 시작할 수 있다. 진행 중인 복사 도우미가 없는 `dobby-copy://home` 링크는 안내만 표시하며 예제 상품을 만들지 않는다.

1. 옷 한 벌을 바닥에 펼치고 소매·목·허리·밑단까지 전체가 보이도록 비춘다.
2. 미리보기에서는 축소한 영상에 Vision 전경 분리만 실행한다. 한 벌 전체로 볼 수 있는 단일 전경이 보이면 윤곽과 반투명 채움을 표시한다. 이는 옷 종류·측정점·깊이 정확도를 보증하지 않지만, 현재 제품 화면은 이 윤곽 인식 상태를 셔터 허용 조건으로 사용한다.
3. 카메라가 준비되고 윤곽이 인식되면 주황색 점과 촬영 가능 상태를 함께 표시한다. 윤곽이 없거나 사라지면 비활성화하며, 초점·노출·배율 조작은 계속 허용한다. 촬영 전에는 종류 분류나 측정점 모델을 실행하지 않는다.
4. 셔터 이후의 새 ARFrame에서 원본 RGB·LiDAR 깊이·카메라 보정 정보를 함께 복사한다. 기존 0.35초 품질 선택 창과 깊이·추적 검사를 유지하며, 라이브 윤곽이나 과거 측정점을 재사용하지 않는다. 고정 사진을 먼저 보여주고 카메라를 멈춘 뒤 백그라운드 작업에서 종류·측정점·측정용 마스크를 확인하고 길이를 계산한다. 처리 중 회전해도 고정 사진의 방향을 유지하며, 화면을 닫으면 늦은 결과를 버린다.
5. 실측 결과의 사진 위에 실제 점·측정선·cm 값이 표시된다. 계산 불가 항목은 수치 대신 원인을, 불확실한 항목은 확인 필요 상태를 표시한다.
6. **다음**은 사진·깊이·측정점·결과를 원래 실측 기록에 저장하고, 확인한 치수·사진을 같은 SwiftData 상품으로 전달한 뒤 **제품 상세 촬영**으로 이동한다. 측정 실험실에서 연 독립 촬영 화면은 기존처럼 저장 후 닫힌다. 결과의 뒤로 버튼은 재촬영한다.

사진의 흰색 측정점을 끌어 이동하는 동안 왼쪽 위 돋보기에서 해당 위치를 3배로 확인할 수 있다. 손을 놓으면 돋보기가 사라지고 같은 사진·깊이에서 관련 치수를 다시 계산한다. **원래 위치로**는 모든 보정을 취소한다. 계산·드래그 중에는 **다음**을 사용할 수 없다.

### 현재 셔터 인식 조건

- 미인식은 회색 점·비활성, 윤곽 인식 후 카메라가 사용 가능하면 주황색 점·활성 상태다. 화면 표시와 실제 촬영 함수가 같은 조건을 사용하며, 함수 안에서도 현재 상태를 다시 확인한다.
- 인식 해제·카메라 중단·튜토리얼·처리 중에는 촬영을 차단한다. 배율 변경·재촬영 후에는 새 윤곽을 기다린다. 초점·노출·배율 자체는 인식 대기 중에도 조작할 수 있다.
- 기존92pt 셔터 테두리는 고정하고 원본 에셋의25pt 주황 점만0.24초 response·0.85 감쇠 spring으로 opacity와 scale을 전환한다. 인식 해제는 즉시 회색으로 돌아가며, 동작 줄이기에서는 등장 효과도 즉시 전환한다. 애니메이션 완료를 기다리는 별도 타이머를 촬영 조건에 넣지 않는다.
- 실시간 윤곽은 전경 분리 결과이며, 상·하의 분류·측정점·길이의 보증은 아니다. 해당 모델 분석은 여전히 새 촬영 이후 실행한다. 아래 과거의 촬영 우선 검증 기록과 달리 현재 상호작용은 이 인식 조건을 따른다.
- UI 회귀11개가 통과했다. 상·하의 대기/인식/해제/재인식에서 실제 셔터 중앙 색상을 검사하고, 비활성 탭 차단·새 인식 후 촬영·인식 전 초점/노출·배율 변경·재촬영·튜토리얼·수평 안내·분석 화면·상품 진입을 확인했다. 동작 줄이기와 iPhone 대상 앱·위젯 빌드도 검증했다. 실제 기기의 인식률·애니메이션 프레임 수치는 별도다. 로그: `/private/tmp/dobby-recognition-shutter.log`, `/private/tmp/dobby-recognition-shutter-device.log`.

촬영 후 자동점 확인에 실패하면 종류 분류·측정점 검출·전경 분리·점과 윤곽 불일치·옷 구조 확인 중 실제로 실패한 단계를 안내한다. 사진이 남아 있으면 다시 촬영하거나 그 사진에서 점을 직접 확인할 수 있다. 종전의 인식 결과 재사용 구현·검증은 [상의 인식 후 실패 개선](Automatic-Garment-Recognition.md#인식-완료-후-긴팔-촬영-실패-개선)의 과거 기록이며, 현재 물리 카메라에서는 새 촬영 후 분석 경로만 사용한다.

치수는 작은 Liquid Glass 캡슐로 표시하며, 해당 두 점 사이 점선의 바로 위에 우선 배치한다. 수직선은 사진의 바깥쪽으로 배치한다. 선이 짧거나 돋보기·다른 치수·측정점과 겹치면 가까운 빈 공간으로 옮기고 연결선으로 해당 구간을 표시한다. 치수의 전체 터치 영역은 서로 겹치지 않으며, 측정점 주변의 넓은 터치 영역은 치수의 여백보다 우선한다. 투명도 줄이기에서는 불투명한 배경을 사용한다. 세로 결과 화면의 오른쪽 위 메뉴에서 사진 확대·측정 항목 상세·원래 위치 복원을 연다. 치수 버튼은 항목 상세 보기로 연결된다. 상세의 수동점 검증은 기존 검증 화면을 사용하며 별도 기록으로 저장된다. 시안 비교와 표시 규격은 [디자인 정교화 #32](#디자인-정교화-32)를 참고한다.

유리 효과는 시스템의 `glassEffect`를 사용하고, 여러 캡슐을 `GlassEffectContainer`로 묶는다. API 기준은 [Apple의 Liquid Glass 적용 문서](https://developer.apple.com/documentation/swiftui/applying-liquid-glass-to-custom-views)를 참고했다.

보정된 위치·치수와 원래 자동 인식 위치·치수를 함께 저장한다. 수정한 점만 수동 보정으로 구분하며, 수정하지 않은 모델 점의 신뢰도 검사는 유지한다. 상의 목 중앙·하의 허리 중앙은 원본 점에서 파생되므로 직접 움직이지 않는다. 상의 총장은 목 좌우와 밑단 중앙을 보정해도 기존 목선에 수직인 3D 계산을 유지한다. 저장 기록을 다시 열 때는 보정된 점으로 재계산한다.

VoiceOver에서는 점을 선택한 뒤 왼쪽·오른쪽·위·아래 이동 동작으로 위치를 조절할 수 있다. 큰 글씨에서는 사진 위 라벨 대신 상세 목록으로 전체 치수를 확인한다.

단계별 캡처에서 상세 촬영의 완료 버튼이 상위 화면의 흰색 tint를 받아 흰 글자가 잘 보이지 않는 문제를 발견했다. 버튼에 파란 tint를 지정하고 화면 대비를 직접 확인했다. 이 변경 후 상세 사진 촬영 → 사진 선택 → 제품 정보 입력의 짧은 화면 확인도 통과했다.

## 지원 범위

- 하의는 번들 `bottom7` 모델의 바지·반바지, 상의는 `top11` 모델의 펼친 긴팔·반팔 상의에 연결되어 있다.
- 종류는 카메라가 자동으로 판별한다. 옷 종류 또는 모델 버전이 바뀌면 촬영 준비의 연속 확인을 다시 시작한다. 판별이 불확실하면 성공 상태나 임의의 실측값을 표시하지 않는다. 자세한 선택 기준과 검증은 [상·하의 자동 판별](Automatic-Garment-Recognition.md)을 참고한다.
- 상의는 어깨너비·가슴 단면·밑단 단면·왼쪽/오른쪽 소매길이·총장 6개 항목을 제공한다. 자세한 기준은 [상의 모델 연결](Top-Recognition.md)을 참고한다.
- 대부분의 측정값은 지정된 점 사이의 3D 직선거리다. 상의 총장은 목 양끝의 3D 가로축 방향 성분을 제외한다. 주름을 펼친 길이나 굽은 봉제선 길이를 복원하는 기능은 아니다.
- LiDAR가 없는 기기와 시뮬레이터의 실제 촬영 경로에서는 실측값을 생성하지 않는다.

## 화면 미리보기

전체 연결 UI 테스트는 Debug의 `--flow-preview --flow-test-store <UUID>`로 고유 저장소를 사용한다. 측정·상세 촬영은 명시적인 합성 fixture이며 제품·실측 기록·사진 파일 모두 UUID 별 테스트 폴더에 저장한다. Release에서는 이 진입점을 사용할 수 없다. 단위 테스트 호스트는 같은 Debug 격리를 `DOBBY_FLOW_TEST_STORE_TOKEN`으로 지정한다.

**촬영 화면 미리보기**는 합성 하의 그림과 합성 깊이로 세 화면의 전환을 확인한다. UI 테스트의 `--garment-preview-top` 실행 인자는 합성 상의 그림을 사용한다. **인식 상태 보기** → 셔터 → 결과 → 확인 또는 인식 표시 전 셔터 → 결과 순서로 확인할 수 있다. 카메라·ML·센서 정확도 검증이 아니며, 화면과 저장 출처 모두 합성으로 구분된다.

UI 테스트의 `--garment-preview-partial` 실행 인자는 합성 미리보기의 일부 점을 제거해 부분 실패 표시를 검사한다. 실제 촬영에는 영향을 주지 않는다.

`--garment-preview-reduce-motion`은 합성 미리보기에서만 동작 줄이기 표시를 검사한다. 시스템 접근성 설정은 변경하지 않는다.

### 상·하의 자동 판별 · 2026-10-01

### 실측 결과 편집 · 2026-10-01

- 고정 폭·2줄 치수 박스를 내용에 맞춘 28pt 높이의 Liquid Glass 캡슐로 변경했다. 숫자와 `cm`가 잘리지 않도록 실제 표시 글꼴의 폭을 사용한다.
- 원본 측정점의 중심은 9pt, 테두리는 기본 15pt·선택 시 21pt이며, 주변 56pt 지름의 원까지 터치할 수 있다. 가까운 점의 터치 영역이 겹치면 이웃과의 중간선을 경계로 나누어 손가락에 더 가까운 점을 잡는다. 주변을 잡아 끌어도 점이 손가락의 첫 위치로 튀지 않도록 원래 점에 드래그 이동량을 더한다. 선택한 점은 주황색이고, 좌측 상단 돋보기에서 같은 사진을 3배로 확인한다. 확대 그림은 작은 Canvas 안에서 그려 사진 밖의 터치·접근성 영역을 만들지 않는다.
- 드래그 중에는 라벨 위치를 유지하고 점·직선·돋보기만 갱신한다. 손을 놓으면 공유 측정점이 쓰이는 항목을 같은 촬영 깊이로 다시 계산한다. 회전·터치 취소는 진행 중인 이동 미리보기를 취소한다.
- 원본 자동 점·치수와 보정 점·치수를 함께 보관하며, 원래 위치 복원과 저장 기록 재열기를 지원한다. 수정하지 않은 모델 점의 신뢰도 검사, 목·허리의 3D 파생점, 상의 총장 투영 계산을 유지한다. 보정 기록은 모델만의 정확도 통계에 포함하지 않는다.
- Core 370개가 통과했다. iPhone 17 Pro / iOS 26.4 시뮬레이터에서 서로 다른 UI 9개·좌표 표시 테스트 9개가 통과했다. 상의 점 이동·치수 갱신·저장·앱 재실행 후 재열기, 하의 원래 위치 복원, 사진·돋보기 접근성 영역, 기존 부분 실패·상세 검토·재촬영·가로 화면을 검증했다. 전체 실행의 실패 3개는 Canvas 적용 후 동일한 조건과 assertion으로 재실행해 통과했다.
- 최종 소스의 네이티브 Debug·Release 기기용 빌드가 서명 없이 통과했다. 이는 실기기 설치 검증이 아니다. [상의 보정 화면](Images/measurement-point-editor-top.png)과 [하의 결과 화면](Images/measurement-point-editor-bottom.png)은 실제 실행한 합성 UI 미리보기다.
- 작은 점·주변 터치·점선 인접 배치 추가 조정 후 최종 실행에서 UI 4개·표시 좌표 테스트 22개, 총 26개가 실패·생략 없이 통과했다. 점 중심에서 17pt 떨어진 곳을 잡아도 위치가 튀지 않고, 24pt 간격의 두 점 중 가까운 점만 움직이는 것을 검증했다. 보이지 않는 캡슐 터치 여백은 점과 겹칠 수 있게 하여 불필요한 긴 연결선을 줄였다. 앞선 실행에서 부적절하게 목의 빈 공간으로 옮긴 합성 테스트는 실제 마스크 검증으로 총장이 계산 불가가 됐으며, 옷 내부의 겨드랑이 점으로 수정해 통과했다. 같은 작업의 중심 드래그·저장 재열기·원래 위치 복원 검증도 앞선 실행에서 통과했다.

이 검증은 합성 미리보기의 UI·계산·저장 계약을 확인한 것이며 실제 센서의 cm 정확도 검증은 아니다. 실행 근거는 [결과 편집 검증 기록](Validation/measurement-result-editing-2026-10-01.json)에 있다.

### 촬영 먼저 · 촬영 후 분석 · 2026-10-03

- 카메라 시작 전 모델 준비와 라이브 의류 분류·측정점 분석을 제거했다. 영상이 준비되면 셔터를 사용할 수 있고, 윤곽 표시 여부는 셔터를 잠그지 않는다.
- 라이브 윤곽은 최대 512px 영상에서 실행하는 단일 Vision 전경 분리 작업이다. 종류·측정점·깊이와 무관한 미리보기이며, 혼잡하거나 잘린 전경에는 표시하지 않는다. 실제 측정의 점·마스크 검증은 변경하지 않았다.
- 물리 카메라는 라이브 분석 프레임을 재사용하지 않는다. 셔터 이후 같은 ARFrame에서 RGB·raw/smoothed depth·보정 정보를 확보하고, 사진을 고정해 보여준 뒤 종류·측정점·길이 순서로 분석한다. 기존 0.35초 프레임 품질 비교를 유지한다.

현재는 윤곽 인식 후 촬영하는 흐름이다. 주황색 점이 나타나야 셔터가 작동하고, 사진·깊이·보정 정보를 확보한 후 같은 사진에서 측정점을 찾고 길이를 계산한다. 윤곽이 없으면 셔터를 비활성화하며, ‘인식 완료’ 안내와 실제 촬영 조건을 함께 갱신한다.

현재 상의6개·하의8개 측정 항목을 모두 유지한다. 시안의4개 예시 값으로 대체하지 않는다. 원본 점·치수, 보정값, 저장 정밀도, SwiftData 전달과 다음 화면 연결은 바꾸지 않는다.

### 화면 구성

- 촬영 화면의 내비게이션·반투명 상하단 조작 영역은 유지하며, 실제 카메라 영상은 그 사이에서 원본 비율을 보존한다. 402×874 기준 상단 영역146pt, 하단 시작y682, 안내y560, 배율y617, 셔터y716(92×92), 더보기48×48이다. 4:3 센서의 세로 사진 영역은402×536pt이며 전체 휴대폰 화면을 채우는 추가 확대는 적용하지 않는다. 작은 화면과 가로 화면은 사진 비율과 조작 영역을 함께 보존한다.
- 촬영 전 배치 안내는 원본 티셔츠·측정점 에셋을 사용한다. ‘다음부터 이 튜토리얼 건너뛰기’를 저장하며 더보기에서 다시 열 수 있다. 사용자가 선택한 대로 체크박스 문구는 Pretendard Regular를 유지하고 SIL OFL 라이선스도 함께 번들에 포함한다.
- 결과 화면은 안전 영역·사진 밖 여백·버튼 주변까지 명시적인 흰색 배경, 기본 내비게이션, 536pt 기준 사진 영역과 ‘다음’ 버튼으로 구성한다. 새 촬영은 셔터 순간의 카메라 구도를 기준으로 표시하고, 실제 표시된 사진 좌표를 점·선·치수·확대기에 공통으로 사용한다. 시안의 예시 치수와 옷 사진을 실제 측정값으로 넣지 않는다.
- 첫 정상 결과에는 측정점을 직접 움직일 수 있다는 안내를 표시한다. 화면을 탭하면 닫히고, 다시 계산하거나 상세 화면에서 돌아와도 반복 표시하지 않는다. 합성 미리보기는 명시적인 테스트 인자에서만 튜토리얼을 표시하며 실제 사용자 선호를 소비하지 않는다.
- 치수 캡슐은11pt/21pt를 기본으로 하며 정수 cm와 작은 Liquid Glass 배경을 사용한다. 측정점 주변56pt 터치 영역과 드래그 때만 나타나는3배 확대기를 유지한다. 확대기는 새 시안의76×107pt로 맞춘다.

### 디자인과 동작의 구분

- 사용자가 시안 위치의 배율 버튼 복원을 선택했다. 48×48pt 원형 Liquid Glass 버튼을 탭하면 메뉴 없이1x↔2x가 즉시 전환된다. 현재 배율과 다음 탭의 동작을 접근성 값·힌트로 제공한다. 실제 측정 경로가 지원하는1x·2x만 제공하며, 다음 배율을 지원하지 않거나 촬영 중이면 버튼을 비활성화한다. 시안의10x를 지원한다고 표시하지 않는다. 합성2x는 고정1x 깊이 데이터를2x 측정으로 오인하지 않도록 촬영을 제한하며1x로 돌아와 새 윤곽을 인식한 후 촬영한다.
- 하단에 별도의 노출 바는 추가하지 않는다. 탭 초점과 탭 시EV0 초기화, 초점 박스 옆 노출 조절, 미리보기 세로 드래그를 유지한다.
- 수평 안내는 Core Motion의 중력 방향을 이용하는 촬영 보조 UI다. 값은 측정 계산·AF/AE·셔터 활성 조건에 전달하지 않으며, 기기에서 방향 값을 제공하지 않으면 강제로 표시하지 않는다.
- 윤곽이 인식되어 셔터 중앙의 주황색 점이 나타나면 촬영할 수 있다. 길이와 측정점은 촬영 후 확보한 같은 사진·깊이에서 계산하며, 촬영 전 윤곽은 계산 결과를 보장하는 표시가 아니다.
- 결과의 상세·사진 확대·원래 점 복원·실패 원인 안내에 접근할 수 있도록 기존 더보기 메뉴는 유지한다. 이는 시안의 기본 결과 화면에 더해진 기능 접근점이다.

### 촬영 구도와 결과 사진

- #101에서 전체 화면 aspect-fill 때문에1x가 추가 확대되던 표시를 수정했다. 402×874 화면에 세로3:4 영상을 채우면 실제402×536 사진 창에 맞출 때보다874/536≒1.63배 커진다. 이제 `CameraPhotoViewport`가 사진 원본 비율을 상·하단 조작 영역 사이에 aspect-fit하며, 실제 ARSCNView도 그 크기를 사용한다. 0.5x 렌즈나 임의 배율 상수를 적용하지 않는다.
- 첫 ARFrame이 전달하는 실제 영상 해상도와 방향으로 사진 창을 계산한다. 셔터 순간에는 휴대폰 전체가 아닌 이 사진 창의 크기를 고정하며, 결과 표시 영역에서도 조작 영역을 다시 빼지 않는다. 1x는 전체 원본, 2x는 기존 RGB·깊이·보정행렬 공통 중앙 크롭을 사용하고 표시 배율을 다시 곱하지 않는다. 가로 화면은 우측180pt 조작 영역을 제외한 공간 안에 사진을 중앙 정렬한다.
- `CaptureSnapshot.presentationCrop`은 회전된 사진 위의 **표시 정보**다. 원본 JPEG·깊이·카메라 보정행렬·측정점과 계산값은 바꾸지 않는다. 사진·점·선·라벨·드래그 역변환·3배 확대기는 하나의 변환을 공유하며, 편집 도중 구도가 움직이지 않도록 영역을 고정한다.
- 이전 기록이나 올바르지 않은 표시 정보는 원본 전체 사진으로 표시한다. 새 표시 정보는 저장·재열기에도 유지한다. 기존 합성 미리보기는 원본 비교를 유지하고, 새 구도 경로는 `--garment-preview-matched-framing`으로 별도 검증한다.
- 분석 중 정지 사진에도 촬영한 실제 사진 창의 구도를 유지한다. 셔터 순간 사진 창 크기를 별도로 고정하며, 기기 회전 시에는 그 창을 비율 유지해 배치한다. 2x 사진에 확대를 다시 적용하지 않는다. 분석·깊이·측정점 계산에는 기존 원본을 그대로 전달한다. 상세 원인·현재 동작·실기기 비교 조건은 [카메라 화각 정렬](Camera-Photo-FieldOfView.md)을 참고한다.
- 분석 화면 회귀 검증은 기하43개·UI2개로45개가 통과했다. 합성 미리보기의 촬영 전과 분석 중6개 지점 RGB를 비교하고, 정지 사진 영역·진행 안내·중복 촬영 방지·결과·재촬영을 확인했다. 회전 시 창 보존과2x 중복 확대 방지는 기하 테스트 범위이며, 실제 iPhone의 광학 결과를 입증하지 않는다. 앱·위젯 빌드도 통과했다. 로그: `/private/tmp/dobby-processing-framing.log`, `/private/tmp/dobby-processing-framing-device.log`.

### 후속 초기 실행 응답성 개선

- 촬영 화면 값의 초기화에서 카메라·인식기 그래프를 만들지 않는다. `GarmentCaptureSession`을 `StateObject`로 유지하고, 앱 범위 `AsyncResourceCache`에서 인식기를 한 번 준비해 재사용한다. 스키마 읽기와 컨텍스트 생성은 UI 실행기 밖에서 수행한다. 이 준비는 모델 예측을 미리 실행하는 작업과 다르다.
- 카메라 시작과 가벼운 서비스 준비는 병행한다. 두 측정 모델 전체 예열을 셔터 조건으로 추가하지 않는다. 현재 셔터는 최신 요청대로 라이브 윤곽 인식을 기다린다. 모델과 측정의 정확도 기준·15초 자동 측정 제한은 바꾸지 않았다.
- 첫 모델 로드 도중 요청이 취소돼도 검증 완료한 분류 모델은 캐시한다. 취소된 사진은 계속 거부하고, 방향 모델도 로드 직후 취소를 확인해 불필요한 예측을 막는다.
- 전경 Vision 요청 취소는 전용 큐로 보내며, 실제 작업이 끝날 때까지 기존 busy/job 소유권을 유지한다. 촬영·라이브 분석의 CIContext도 전용 직렬 큐에서 처음 필요할 때 생성한다.
- 보관함·제품 사진의 파일 열기와 썸네일 디코딩은 별도 actor로 이동했다. 디코딩 크기는4096px 이하, 캐시는32MiB·64장 이하이며, 취소되거나 새 요청으로 바뀐 이미지·로드 콜백은 UI에 반영하지 않는다. SwiftData 모델과 컨텍스트는 UI 실행기에 남긴다.
- 시작 시 디버그 샘플 사진을 자동으로 대량 생성하는 경로만 제거했다. 사용자가 디버그 샘플을 직접 여는 기능은 유지한다. 비상호작용 안내 문구는 카메라 초점 탭을 가로채지 않도록 했다.
- 첫 실행 비용의 실제 비율은 실기기에서 측정한다. `com.dobby.performance`의 `CaptureServicePreparation`, `CameraPreviewStartup` 구간과 `CameraFirstPreviewFrame` 이벤트, `GarmentClassifierModelLoad`, `GarmentOrientationModelLoad` 구간을 Core ML·Time Profiler와 함께 본다. 프레임 이벤트 없이 종료된 시작 구간은 첫 프레임 완료로 해석하지 않는다.
- [Apple의 Core ML 성능 분석 문서](https://developer.apple.com/documentation/coreml/analyzing-a-core-ml-model-s-performance-in-xcode)는 캐시되지 않은 로드와 첫 예측 비용을 이후 실행과 구분한다. [앱 응답성 안내](https://developer.apple.com/documentation/xcode/improving-app-responsiveness)에 따라 UI 실행기의 동기 I/O·디코딩을 분리했으며, 소프트웨어 회귀 테스트를 실기기 속도 개선 수치로 제시하지 않는다.
- 검증: 공유 준비·취소·시간 초과·촬영 우선 순서35개, 사진 디코딩6개, 카메라 조작4개, 결과 구도·저장1개, 미지원 기기1개, 상품 생성 전체 흐름1개로 서로 다른48개가 통과했다. 상품 흐름은 현재 첫 촬영 안내·사진 그리드·최대10장 안내를 기준으로 검증했다. 초점 탭을 가로채던 안내는 수정 후 집중 테스트를 다시 통과했다. 앱·위젯 iPhone 대상 Debug 빌드와 `git diff --check`도 통과했다.
- 로그: `/private/tmp/dobby-cold-start-core.log`, `/private/tmp/dobby-cold-start-ui.log`, `/private/tmp/dobby-cold-start-focus.log`, `/private/tmp/dobby-cold-start-product-final.log`, `/private/tmp/dobby-cold-start-device-final.log`. 실제 iPhone의 첫 실행 전후 시간·프레임 수치는 아직 측정하지 않았다.

### 실측 촬영 더보기 · 노출과 사진 비율 (#105)

- 우측 하단 더보기는 화면을 덮는 별도 시트 대신 기존 촬영 화면 위의 하단 옵션 패널로 전환한다. 촬영 버튼·배율·안내는 자리를 유지한 채 숨겨지며, 사진 창과 ARSession은 그대로 유지한다. 바깥 사진 탭은 전체 옵션을 닫고, 각 설정의 뒤로가기는 메뉴로 돌아간다. 다시 열면 메뉴에서 시작한다.
- Mason의 `DetailCaptureOptionsView`·`DetailExposureView`·`DetailAspectRatioView`를 재사용한다. 기본 상세 촬영은 `.standard`, 실측은 `.measurement` 표시를 사용한다. 실측 메뉴↔하위 패널은 response0.30·damping0.90의 짧은 전환을 사용하며, 동작 줄이기는 이동 없이0.12초 opacity로 전환한다. 큰 글자와 좁은 가로 화면은 세로 선택·스크롤로 대응한다.
- 메뉴 열기/닫기와 사진 비율 변경은 서로 다른 애니메이션이다. 사진 비율은 실제 UIKit 카메라 창의 크기와 위치를0.30초 동안 보간하며, 그동안 촬영을 막아 중간 크기와 촬영 메타데이터가 섞이지 않도록 한다. 전체 휴대폰 화면을 채워 추가 확대하는 #101 이전 방식으로 돌아가지 않는다.
- 기존 촬영 가이드 다시 보기는 옵션 메뉴에서 유지한다. 메뉴가 열린 동안 사진 초점·노출 팬과 셔터는 옵션 선택과 경쟁하지 않는다. 옵션을 닫으면 현재 인식 상태에 따라 주황색 셔터가 복귀한다.
- 사진 프레임 바깥 전체는 같은 카메라 RGB를 흐리게 비추는 반투명 배경으로 처리한다. 이 배경은 주변 색을 보여주는 장식용 재표시이며 실제 추가 촬영 시야가 아니다. 기존 중앙 ARSCNView의 크기·초점·윤곽·촬영 크롭은 그대로 유지하고, 주변 배경은 터치나 측정에 참여하지 않는다.
- 실기기의 장식 배경은 같은 ARSession의 최신 RGB를 별도 큐에서 최대320px·10fps로 작게 렌더한다. 처리 중에는 프레임을 건너뛰고 버퍼 한 개만 유지하며, 추가 ARSession·ARSCNView를 만들지 않는다. 회전·배율·세션·화면 상태가 바뀌면 오래된 렌더 결과를 버린다. 촬영 중에는 갱신을 멈추고 준비된 정지 사진으로 전환한다.

노출 연결:

- `GarmentCaptureSession`이 공용 옵션 모델을 안정적으로 소유한다. `LiDARDetailCameraControls`는 별도 AVCaptureSession을 만들지 않고 기존 ARKit 제어 worker의 실제 수락 receipt를 반환한다. 이 값은 센서 밝기가 완전히 정착했다는 보증과 구분한다.
- 더보기 눈금, 초점 탭의 EV0 초기화, 사진 위 세로 드래그가 같은 카메라 노출 상태를 공유한다. 메뉴를 닫아도 최신 대기 요청은 유지하며, 아직 제출 중인 메뉴 요청이 있으면 완료 전 촬영하지 않는다. 기존 직접 팬의 즉각적 UI 표시와 촬영 barrier는 유지한다.
- 새 초점·세로 팬 입력은 이전 메뉴의 대기 노출 요청을 동기 취소한다. deferred Combine 동기화보다 먼저 큐를 비워, 오래된 메뉴 값이 새 EV0 뒤에 재제출되지 않게 한다. 대기 메뉴 요청이 없으면 이 경로는 상태를 발행하지 않는다.
- 세션 교체·중단·취소·supersede와 적용 실패를 분리하고 늦은 receipt를 버린다. 공용 노출 UI도 드래그 도중 이전 receipt로 눈금을 되돌리지 않는다.
- 실측의 노출 눈금은 사용자가 표시상0.1EV 단계를 바꿀 때 [선택 햅틱](https://developer.apple.com/documentation/swiftui/sensoryfeedback)을 요청한다. 초기 표시·외부 노출 동기화·초기화 버튼·한계의 동일 값·적용 재시도는 추가 진동을 만들지 않는다. 카메라의 Float EV 수락값과 UI Double 사이의 작은 오차도 같은 표시 눈금으로 취급한다.
- 중앙 노란 표시선은 고정된44pt 터치 영역 안에서16→36→16pt로 변한다. 손을 대면 늘어나고 손을 떼거나 제스처가 취소되면 복귀하는 짧은 스프링(response0.22·damping0.86)을 사용한다. 동작 줄이기에서는 길이를 즉시 전환한다. 이 애니메이션은 장식 표시선에만 적용하며 노출값·카메라 요청을 보간하거나 기다리게 하지 않는다. 기존 상세 촬영의28pt 표시선과 햅틱 동작은 유지한다.

- 선택은4:3·16:9·1:1이다. 기본4:3은 실제 원본 전체를 유지해 기존1x·2x 구도를 보존한다. 비표준 합성/가져오기 사진도 기본 모드에서는 원본을 유지한다. 나머지는 회전된 사진에서 정확한 중앙 표시 영역을 계산한다.
- 원본 JPEG·깊이·intrinsics·ML 입력·측정점 좌표는 변경하지 않는다. 2x의 등록된 RGB·깊이 크롭 이후 선택 비율의 표시 크롭은 한 번만 적용한다. 촬영 직후 분석 화면은 셔터 순간의 창을 고정한다.
- `CaptureSnapshot.capturePresentationCrop`은 선택한 촬영 창, `presentationCrop`은 결과 사진의 실제 표시 창이다. 기존 기록은 새 필드가 nil이어도 열린다.
- 선택 비율 밖에 정상 측정점이 있으면 검증에서 버리지 않고 결과의 사진 영역을 넓힌다. 이 경우에만 “측정점을 모두 볼 수 있도록 사진 영역을 넓혔어요”라는 중립 안내를 표시한다. 측정 실패 경고나 느낌표로 취급하지 않는다. 사진·점·선·확대기·점 이동은 넓힌 동일 표시 변환을 사용한다.
- 메뉴 선택은 해당 촬영 세션에서 유지하며, 앱 재실행 후 설정 영구 보존을 추가한 것은 아니다.

### 일반 카메라 + 실제 초광각 주변부 (MultiCam)

- 위의 10fps·320px 장식 배경 구현은 교체했다. 실제 촬영 화면은 `LiDARMultiCameraCapture` 한 세션이 일반 RGB·LiDAR 절대 깊이·초광각 RGB를 동기화하고, 하나의 `MultiCameraPreview` Metal 화면에서 합성한다. 자세한 계약과 실기기 검증 범위는 [MultiCam 미리보기](MultiCam-Measurement-Preview.md)를 참고한다.
- 중앙 사진 창은 전체 일반 카메라 1x와 기존 등록된 2x 크롭을 유지한다. 비율/2x 선택 때문에 중앙 창 밖에도 일반 카메라 원본 픽셀이 있으면 그대로 이어 보여주고, 일반 카메라 범위 밖만 실제 초광각으로 채운다. 주변부는 GPU의 검정 틴트가 아니라 실제 `.glassEffect(.regular)` 한 장으로 처리하며 사진 창은 투명하게 비운다.
- 기존 ARKit을 동시 실행하지 않는다. 실제 기기의 조합·보정 정보·비용을 확인한 후 MultiCam을 실행한다. 지원하지 않으면 ARKit 단일 카메라로 순차 폴백하고, 주변을 가짜 확대 영상으로 채우지 않는다.
- AVFoundation 깊이는 `.avFoundationLiDAR`로 구분한다. 사진과 깊이 모두 같은 렌즈 보정 좌표계로 변환한다. AR 추적이나 픽셀별 confidence가 있다고 가정하지 않는다.
- 세로 비율별 사진 창은 전체 너비를 우선하며 16:9는 셔터 뒤까지 이어진다. 배율 버튼은 사진 하단에 맞춰 이동하고 셔터 영역 앞에서 제한한다. 셔터·더보기는 고정하고, 사진·글라스 마스크·배율 위치가 같은 비율 애니메이션을 따르도록 한다. 원본 RGB·깊이·K와 측정점 좌표는 변경하지 않는다.
