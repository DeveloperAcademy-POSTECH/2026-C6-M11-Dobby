# LiDAR 모듈 인수·연결 안내

갱신일: 2026-09-28 · 대상 브랜치: `feat/3-LiDAR-Module` · 최종 마감: 2026-09-30

팀 합의에 따라 화면은 MV 구조를 사용한다. 입력·알림 상태는 View, 측정 데이터는 값 Model, 자동 흐름·시도 기록은 서비스가 담당한다. 화면별 ViewModel은 없다. 구조와 확장 규칙은 [MV 아키텍처 문서](LiDAR-Architecture.md)에 정리했다.

## 완료한 소프트웨어와 남은 인수 조건

| 단계 | 구현 상태 | 외부 입력이 필요한 검증 |
| --- | --- | --- |
| 공통 계약·거리 코어 | 완료 | 팀의 측정점 정의·좌우·총장 기준 합의 |
| 실기기 기준선 도구 | 촬영·A/B·저장·재계산·줄자 비교 구현 | iPhone 17 Pro의 실제 촬영과 줄자 정답 |
| 깊이 안정화 | 표본 필터·국소 평면·프레임 선택·원본/평활화 비교 구현 | 같은 실측 세트의 오차·실패율로 채택 판정 |
| 자동 측정 연결 | 촬영→ML→계산→전체 항목 표시·저장·취소 구현 | 메이슨·이치의 실제 구현 주입 및 기기 검증 |
| 최종 검증·인수 자료 | 조건별 보고서·시도 기록·단계 시간·CSV·Markdown 구현 | 실물 정확도·지연·메모리·발열·지원 조건 확정 |

이 문서의 ‘구현 완료’는 실물 검증 완료나 모든 의류 자동 인식을 뜻하지 않는다. 현재 앱에는 실제 학습된 의류 모델이 연결되어 있지 않다. 기본 자동 촬영 버튼은 이 상태를 표시하며, 합성 연결 테스트는 실제 측정과 분리된다.

## 앱에서 바로 확인하기

1. `Dobby/Dobby.xcodeproj`의 Dobby scheme을 시뮬레이터 또는 사용자가 직접 설치한 LiDAR 기기에서 실행한다.
2. **합성 자동 연결 테스트**를 실행한다. 50cm 전체 구간·25cm 절반 구간과 의도적으로 빠뜨린 측정점의 실패가 한 화면에 표시된다. 이는 모델이 옷을 인식한 결과가 아니다.
3. 항목별 줄자 기준값을 입력하고 **전체 항목 기록 저장**을 누른다. 저장한 항목을 다시 열면 현재 엔진으로 전부 재계산한다. 실패 항목도 유지한다.
4. **이 사진에서 수동점 검증**으로 같은 사진의 한 항목을 다시 확인할 수 있다. 모델 점을 수동으로 고치기 시작하면 나머지 점도 직접 확인해야 한다. 자동 결과·수동 결과를 둘 다 저장하면 같은 촬영의 편차가 최종 보고서에 나타난다.
5. **최종 검증 · 시도 기록**에서 수동점과 모델점의 오차, 조건별 반복 편차, 촬영 전 실패·취소·시간 초과와 처리시간을 확인한다. 실제 기록이 없으면 실물 정확도와 인수 판정은 대기로 남는다.
6. 검증 CSV·검증 Markdown·시도 CSV를 각각 공유할 수 있다. 원본 이미지·깊이 재현에는 개별 측정 JSON을 사용한다.

합성 테스트 저장이나 실행은 실측 표본 수를 늘리지 않는다. 설치·커밋·푸시·외부 전송은 이 작업에서 수행하지 않는다.

## 메이슨: 카메라 연결

공통 `CaptureSnapshotProviding`는 Core에 있다. 카메라 화면과 AR/AVFoundation 세션은 메이슨의 구현 하나가 소유하고, workflow에는 그 provider를 주입한다.

```swift
let workflow = AutomaticMeasurementWorkflow(
    camera: cameraProvider,
    landmarks: modelProvider,
    definitions: MeasurementDefinition.longSleeve,
    expectedLandmarkOrigin: .model
)
let output = try await workflow.run(orientation: orientation)
// output.snapshot, landmarks, result, definitions, options, timings 사용
```

workflow 인스턴스는 재촬영마다 새로 만들지 말고 유지한다. 취소를 무시하는 provider의 실제 작업은 인스턴스당 최대 2개(현재 작업+종료 대기)로 제한한다. 상한에 도달하면 새 요청은 busy로 끝난다. 구현체도 Task 취소에 응답하고 보관한 버퍼를 해제해야 한다.

- 카메라는 원본 RGB·깊이·보정값을 같은 프레임으로 묶는다. 자세한 좌표 규약은 [연동 계약](LiDAR-Integration.md)을 따른다.
- `AutomaticMeasurementFailureClassifying`를 구현하면 timeout/interrupted/cancelled 같은 원인을 보존할 수 있다. 일반 Error도 처리하지만 원인이 일반 providerFailure로 남는다.
- 현재 ARKit 어댑터는 촬영 후 추론 동안 세션을 정지한다. 모델 실패 후에는 같은 촬영 화면에서 세션을 다시 시작한다.
- 카메라/ML 호출의 기본 제한은 전체 15초이며 캡처 어댑터 자체의 제한은 4초다. 제한은 최적 성능 보장값이 아닌 UI 대기 상한이다.

## 이치: 의류 ML 연결

기존 `GarmentLandmarkProviding`를 구현하고 `snapshot.imageJPEG`를 실제 추론 입력으로 사용한다. 동일 sessionID/frameID, 원본 전체 이미지 좌표, `.model` 출처와 비어 있지 않은 모델 버전을 반환한다. 신뢰도 점수 누락을 임의의 높은 점수로 채우지 않는다.

현재 실험 화면의 연결 지점은 다음과 같다.

```swift
LiDARLabView(landmarkProvider: modelAdapter)
```

이 줄의 `modelAdapter`는 팀이 제공할 구현체다. 저장 모델 파일이나 출력 tensor 형식이 없는 상태에서 임의 모델을 생성하거나 다른 앱의 검출기를 실제 모델로 표시하지 않는다. 모델 입력의 리사이즈·크롭·패딩·회전은 어댑터에서 원본 좌표로 되돌린다.

한 항목의 점을 찾지 못하면 누락 상태를 그대로 전달한다. 엔진은 가능한 항목을 유지하고 나머지에 실패 사유를 붙인다. 다른 프레임의 점, 잘못된 출처, 모델 버전 없는 실제 모델 결과는 자동 측정 화면으로 보내기 전에 거절한다.

## 저장·기록 계약

- `SavedMeasurement` 버전 1을 유지하며 `referenceByDefinitionCentimeters`를 선택 필드로 추가했다. 여러 항목은 각 ID별 줄자값을 기록한다. 기존 단일 줄자값은 단일 항목 기록에서만 해석한다.
- 측정 파일의 ID는 불변이다. 수정 저장은 새 기록 ID를 사용하고 보고서가 같은 촬영·항목·출처의 최신 저장만 유지한다.
- `LiDARMeasurements`는 이미지·깊이·점과 재계산 자료, `LiDARAttempts`는 작업 시작/종료·원인·처리시간을 담는다. 시도 기록에는 사진과 깊이를 넣지 않는다.
- 시도 기록은 셔터 처리 전에 시작한다. 수동 검증은 촬영까지, 자동 측정은 사진→측정점→계산까지를 한 시도로 정의한다. 따라서 두 목적의 처리시간·성공률을 섞어 비교하지 않는다.
- 취소와 미완료를 실패에 몰아넣지 않는다. 앱이 중간에 종료되어 종료 기록이 없으면 미완료로 남는다. 같은 시도 ID의 중복 완료 호출은 첫 결과를 바꾸거나 표본 수를 늘리지 않는다.
- 자동 측정 전체 항목 계산 완료율은 취소를 제외한 자동 terminal 시도를 분모로 한다. 촬영·모델 실패도 분모에 포함한다. 이는 센서의 실제 정확도가 아니다.

## 최종 보고서 해석

보고서는 저장된 사진·깊이·측정점으로 현재 거리 엔진을 재실행한다. 과거 모델을 다시 추론한 결과는 아니다. 수동점·자동점, 기기, 의류 종류, 물체 이름, 조건, 항목·점 정의, 깊이 출처, 모델 버전과 계산 옵션을 구분한다. 미기록 조건을 추정해 채우지 않는다.

같은 프레임의 자동−수동 편차는 측정점 선택에 따른 차이이고, 줄자 대비 오차와 구별된다. 사진·깊이·보정값·정의·설정이 같은지 확인한 후 비교한다. 두 결과는 같은 촬영이므로 독립 촬영 2회가 아니다.

MAE 1cm·P95 2cm·수치 산출률 90%는 제안 기준이다. 충분한 정답 비교가 없으면 표본 부족이며, 수치 기준을 충족해도 실제 인수 검토를 요구한다. 모든 소재·거리의 성능 보장으로 표시하지 않는다.

## 실기기 인수 때 확인할 사항

- iPhone 17 Pro 카메라 권한, 백그라운드·잠금·복귀, 촬영/추론 도중 취소, 실패 뒤 재촬영.
- 네 방향에서 원본·프리뷰·측정점의 좌표 일치.
- 평면/기울기와 거리·소재별 줄자 오차·실패·반복 흔들림. 원본/평활화 깊이는 같은 프레임으로 비교.
- 실제 모델 점과 사람이 확인한 점의 같은 사진 비교.
- 전체 촬영 시도 수, 결과가 나오기 전 실패, 단계별 지연, 지속 사용 시 발열·메모리. Mac/시뮬레이터 테스트를 센서 성능으로 바꾸어 설명하지 않기.

현재 실행한 소프트웨어 검증 결과와 남은 한계는 [검증 기록](LiDAR-Validation.md)에 기록한다.
